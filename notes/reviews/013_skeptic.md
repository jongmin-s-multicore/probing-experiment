## 요약
- 두 판정 모두 `criterion_not_met` 이다. 그런데 이 실험 구조로는 "not_met" 도 "level_mean_match 의 작은 양의 Δ_use" 도 "크기 정보 사용"에 대해 거의 아무것도 말하지 못한다고 본다. 이유는 세 가지다. (1) 소거가 predictor 가 접근하는 정보에서 크기를 지우지 못한다(블록 1 에서 linear R² 가 0.64-0.79 로 회복). (2) 주 지표 `motion` 은 입력 변위를 출력으로 얼마나 통과시키는지에 수학적으로 좌우된다. 크기 방향 변위는 무작위 방향보다 더 많이 통과되며, 이는 random-init predictor 에서도 똑같이 나타난다. (3) Δ_use 의 귀무값이 0 이 아니다(random-init 의 LEACE 값 약 -0.68, level_mean_match 값 약 -0.18; 가설 문서는 "약 0" 을 예상했다).
- 코드 수준의 누수나 계산 버그는 찾지 못했다. 지표 정의, norm 일치, 무작위 대조 부호, 소거 위치, 적합/평가 분리는 의도대로 구현되어 있다(확인). 문제는 구현이 아니라 설계와 해석에 있다.

  - leace: single_ind seed 0/1/2 = 0.671/0.645/0.711, multi_60_ind_160 seed 0 = 0.722.
  - level_mean_match: single_ind 0.693/0.708/0.766, multi seed 0 = 0.634.
  - 블록 6 은 소거 없음(0.81-0.85)과 거의 같은 0.81-0.88 로 돌아온다.
- 블록 0 의 "소거 확인"은 구성상 거의 자명하다. 소거기(패치 평균에 적합한 스칼라 LEACE, 또는 레벨 평균 맞추기)와 판독기(`linear_pooled`, 패치 평균 위의 선형 회귀)가 같은 함수 계열이기 때문이다. 블록 0 이 0 근처라는 사실은 "선형-풀링 판독기에게는 지워졌다"는 뜻일 뿐이고, 토큰 수준(공간적) 크기 정보가 남았는지는 말해 주지 않는다.
- 블록 1 의 회복은 첫 attention/MLP 블록 하나만 지나도 크기 정보가 선형-풀링으로 다시 읽힌다는 뜻이다. 따라서 predictor 의 계산은 소거 뒤에도 크기 정보에 접근한다. 예를 들어 천이 덮는 패치 수가 그대로 남는다(README 47행이 스스로 인정한 경로). 이 상태에서 Δ_use 는 "크기 정보를 뺐을 때의 비용"이 아니라 "특정 방향의 변위를 넣었을 때의 비용"이다.
- 그러므로 leace 의 not_met 과 level_mean_match 의 not_met(조건 1, 3 충족) 모두 "사용 여부"의 증거로 읽을 수 없다. README 20행의 단서("검출되지 않아도 사용하지 않는다가 아님")는 맞지만, 실제로는 그보다 강하게 말해야 한다. 이 설계에서는 양성 결과가 나왔더라도 "크기 정보 사용"이라 부르기 어렵다(C2, C3 참고).
- attentive 판독기가 없다. 블록 1 에서 이미 linear 로 회복되므로 결론에는 영향이 없다. 다만 블록 0 에서 토큰 수준 판독기(attentive/MLP)로 크기가 그대로 읽히는지 재지 않아서 "입력에서 무엇이 지워졌나"가 정량화되지 않았다. 012 기록(log.md 363-365행)에서는 소거 후에도 MLP/attentive 판독이 유지되었다. 013 입력 위치에서도 같을 것으로 추정한다(013 에서 측정하지 않음).

### C2. 주 지표 `motion` 은 "변위 통과율"의 함수이고, 그 통과율이 방향에 따라 다르다. Δ_use 의 부호가 지표 선택으로 뒤집힌다 (확인 + 유도값)
- 정의(확인, `core.py` 64-74행): z_e = z + δ 일 때 motion = mean((pred − z_e) − (z1 − z))² = mean((pred − z1) − δ)². 따라서 표본마다 정확히 다음이 성립한다.
  `motion = total + |δ|²/(P·dz) − 2·mean((pred − z1)·δ)`
  predictor 가 변위를 그대로 통과시키면(pred − z1 ≈ δ) motion 은 작아지고 total 은 커진다. 변위를 "되돌리면"(pred ≈ z1) motion 은 |δ|² 만큼 커진다. 즉 motion 은 동역학 예측의 질보다, 입력 교란을 통과시키는지 교정하는지에 먼저 반응한다. CHANGES.md 2 의 의도("겉모습 복사 실패를 분리")와 반대로, 겉모습을 교정하는 모델이 벌점을 받는다.
- 유도값(abs_means_over_episodes, 위 항등식, dz = 384, split train). 통과율 = cross / (|δ|²/(P·dz)):
  - (b) seed 0, trained, leace: 크기 0.433, 무작위 평균 0.221.
  - (b) seed 0, trained, level_mean_match: 크기 0.513, 무작위 0.192.
  - (b) seed 0, random_init, leace: 크기 0.545, 무작위 0.312.
  - 크기 방향 변위는 무작위 방향의 약 2배 비율로 출력에 남는다. **학습하지 않은 predictor 에서도 그렇다.**
- 그 결과 부호가 지표에 따라 갈린다(확인):
  - (b) seed 0 leace: Δ_use(motion) = -0.179 [-0.186, -0.171], Δ_use(total) = +0.589 [0.571, 0.606].
  - (a) seed 0 leace: motion -0.167, total +0.481.
  - (b) seed 0 level_mean_match: motion +0.023, total +0.096 (gap 의 16.8%, 10% 기준 초과).
  - (a) seed 0 level_mean_match: motion -0.021, total +0.066.
- 해석: 사전 지정된 판정 지표는 motion 이므로 판정 자체는 규칙대로다. 그러나 "LEACE 크기 소거가 무작위보다 움직임 예측을 덜 망친다(Δ_use < 0)"를 사실로 서술하면 안 된다. 그것은 지표 구성이 만든 결과일 가능성이 높다(추정). 반대로 total 기준의 큰 양수도 "사용"이 아니다. 크기 방향 변위가 더 많이 통과된 결과로 똑같이 설명된다.
- 절차 문제: motion 의 이 정의는 실험자가 정한 것이다(CHANGES.md 2, log.md 355행 "사람 확인 필요"). hypotheses.md 428행은 "(B) 움직임 오차 = Δz 오차"라고만 적었다. 결과를 보기 전에 사용자가 이 정의를 확인했다는 기록을 찾지 못했다. 이 정의가 판정을 사실상 결정하므로 사전 확정 여부를 보고서에 명시해야 한다.

### C3. Δ_use 의 귀무값이 0 이 아니다. 방향 기하가 학습된 사용과 섞여 있다 (확인)
- `random_init_delta_use_reference`(motion): leace -0.681/-0.681/-0.689, level_mean_match -0.179/-0.179/-0.179. 두 조건에서 거의 같다(인코더와 init seed 가 같으므로 당연). hypotheses.md 434행의 예상은 "약 0" 이었다.

- 따라서 "크기 방향 대 무작위 방향"이라는 대조는 사용이 없을 때 0 이 되는 대조가 아니다. 판정 규칙은 0 을 기준으로 삼으므로 귀무 위치가 잘못 지정되어 있다.
- 반대 방향의 위험: random-init 을 귀무로 두고 빼면 level_mean_match (b) 는 0.0196 − (−0.179) ≈ +0.20(gap 의 약 35%)이 되어 "강한 사용"처럼 보인다. 이것도 정당화되지 않는다. random-init 의 오차 척도는 motion_norm_none 5.74 로 학습 모델(0.43)과 다르고, 변위 통과율도 다르다(C2). **결과를 본 뒤 귀무를 바꾸어 결론을 뒤집는 해석은 사후 선택이므로 금지해야 한다.** 이 실험에서 그나마 통제된 비교는 같은 구조, 같은 소거에서 학습 데이터만 다른 (b) 대 (a) 차이다. level_mean_match 의 seed 평균 차이는 0.0196 − (−0.0254) = 0.045 이다(C4 의 교란 참고).

## 중요

### I1. LEACE 를 토큰마다 적용해서 생기는 과도한 변위와 분포 밖 입력 (확인 + 추정)
- 확인(`core.py` 44, 55행): 패치 평균에 적합한 (mu, a, c) 로 **토큰마다** coef = a·(z_p − mu)/(a·c) 를 계산해 빼고, 모든 토큰의 a-성분을 상수 a·mu 로 붕괴시킨다. 패치 평균 수준에서는 LEACE 와 같지만(선형이므로), 토큰 수준에서는 a 방향의 토큰 내 변동 전체와 패치 위치별 평균 차이까지 지운다.
- 확인(abs_means): leace 크기 변위의 토큰별 평균 norm 은 14.659 이고, |δ|²/(P·dz) = 359.11/384 ≈ 0.935(유도값)이다. 이는 프레임 간 실제 변화 persist 0.517 의 약 1.8배다. level_mean_match 변위는 3.759 로, 학습 레벨 레벨 평균 이동 norm(a060 4.63, ind 2.15, a160 4.49; `fit.level_mean_match.mean_shift_norm_by_level`)과 같은 크기다. LEACE 변위는 레벨 평균을 맞추는 데 필요한 크기의 약 3-4배다. 대부분이 크기와 무관한 토큰 수준 내용 제거라고 추정한다.
- 결과(확인): (b) 학습 seed 평균 motion/persistence 는 0.434 에서 1.548 로 오른다(log.md 388행, results.json 과 일치). total 기준으로도 크기 소거 후 normalized 0.695/0.517 ≈ 1.34(유도값)로 persistence 보다 나쁘다. 입력이 학습 분포 밖이라는 강한 신호다.
- 무작위 대조는 이 "정보 붕괴"와 맞춰져 있지 않다. 무작위 변위 −coef·|c|·R_k 는 a-성분을 지우지 않고 새 방향에 같은 크기의 신호를 더한다. norm 은 정확히 같지만(확인, `norm_matching` 최대 차 5.8e-7) 제거되는 정보량은 같지 않다. 크기 소거는 차원 하나를 없애고, 대조는 아무것도 없애지 않는다.

### I2. level_mean_match 의 무작위 대조는 구조가 다르다. 데이터 다양체 위 대 밖의 차이가 대안 설명이다 (확인 + 추정)
- 확인(`core.py` 58-61행, `lib.py` 154-156행): 크기 변위 D[l,p] 는 패치마다 방향이 다르고, 실제 토큰 평균의 차이이므로 데이터 다양체 방향이다. 대조는 모든 패치에 같은 무작위 방향 R_k 를 쓰고 (레벨, 패치)별 부호만 ±1 이다. 384차원 등방 방향은 대부분 다양체 밖일 것이다(추정).
- (b) seed 0 에서 크기 증가 0.110 은 20개 무작위 방향 전부(0.084-0.092, `rand_increase_by_direction`)보다 크다. 이 양의 Δ_use(0.0196 평균, gap 의 약 3.5%)는 "크기"의 효과가 아니라 "그럴듯한 겉모습 변화 대 비현실적 교란"의 차이로도 설명된다. 크기와 무관한 다양체 위 평균 이동(레벨 라벨을 섞은 레벨 평균 맞추기, 또는 시간 단계별 평균 맞추기)을 대조로 두지 않으면 둘을 구별할 수 없다.
- CHANGES.md 5 의 "부호를 무작위로 해 합이 0 이라는 성질을 유지한다"는 정확하지 않다. 9개 레벨에 독립 ±1 을 붙이면 합은 기댓값만 0 이다(사소하지만 문서 정정 필요).
- CI 가 좁은 것(예: seed 0 [0.021, 0.024])은 episode 재표집만 반영한다. 고정된 20개 방향과 고정된 적합에 조건부인 CI 다. 통계적 유의성과 효과 크기를 혼동하지 말아야 한다. 조건 2(10% 기준)는 크게 미달이다(0.0196 < 0.0566, 확인).

### I3. 조건 3((b) > (a))의 교란: 판정 split 이 (a) 에게는 2/3 가 분포 밖이다 (확인)
- 판정 split 은 a060/ind/a160 의 test episode 다(`stages.py` 447행 roles == "trained"). `single_ind` 는 ind 만으로 학습했으므로 a060 과 a160 은 (a) 에게 OoD 다. 소거 없음 gap 도 (a) 0.471 대 (b) 0.573(seed 0)으로 다르다.

### I4. 0단계 관문은 "크기별 동역학 차이"를 보여 주지 않는다 (확인 + 추정)
- 회귀기 입력이 패치 평균 z 이고 z 는 크기를 선형으로 담는다(소거 없음 판독 R² 0.83). 따라서 레벨 A 회귀기를 레벨 B 에 적용하면 동역학이 같아도 공변량 이동(z 분포 차이)만으로 오차가 커질 수 있다.
- persistence MSE 가 레벨마다 다르다(a060 0.0760, ind 0.0838, a160 0.0896; `gate.record.persistence_mse_by_test_level`). 큰 천이 더 많은 패치를 덮어 같은 물리적 움직임에서도 Δz 가 커지는 렌더링 효과로 설명될 수 있다(추정).
- 관문 통과(5/6)는 "레벨 간 Δz 통계가 다르다"까지만 보여 준다. 물리 동역학 차이는 보여 주지 못한다. 비도 비대칭이다(a060→a160 1.459 대 a160→a060 1.272, ind→a060 1.039 미통과). 같은 이유로 2단계의 (b) 상관 0.461/0.477/0.555(대 (a) -0.029/-0.040/-0.050)도 "크기에 따른 겉모습 변화량의 학습"과 구별되지 않는다. 판정에 쓰지 않는다는 원래 규정을 유지해야 한다.

### I5. 판독 확인의 누수와 범위 (확인)
- README 54행과 `stages.py` 361행: 판독 probe 는 학습 split 전체(LEACE 적합 450 episode 포함)의 소거된 특징으로 학습된다. 적합 episode 에서는 LEACE 가 패치 평균 선형 공분산을 표본 내에서 정확히 0 으로 만든다. 그래서 probe 가 약해져 블록 0 R² 가 더 낮게(소거가 더 완전하게) 보이는 쪽으로 치우친다. 블록 1 이후 회복이 크기 때문에 결론 방향은 바뀌지 않는다.
- level_mean_match 의 OoD 레벨에서는 적합 절반이 판독 평가에도 들어간다(README 54행, stages.py 384행 note). interp/extrap 블록 0 이 더 낮게 보일 수 있다.
- 1단계 Δ_use 계산에는 누수가 없다(확인): LEACE 는 train 행에만 적합(`compute_fit` assert, `fit_episode_rows` 최대값 < 900)하고 평가는 test 행이다. 레벨 평균은 학습 레벨이면 train split, OoD 이면 적합 절반이며, 평가 절반과 겹치지 않는다(`stages.py` 135행 assert, `sets_for` 가 level_mean_match 에 eval half 만 사용).

## 사소

- S1. 재현성: `pilot: true` 다. 이유는 "config.yaml pilot flag is true" 이고, 내용은 2 조건 x 3 seed x 900 episode 전체다. `git_status_dirty: true`(head 5d6b165). `code_version` 은 `git status --porcelain -- <exp_dir>` 로 계산되는데(`base.py` 117행), .gitignore 에 logs/·results/ 가 없어서 실행 중 생긴 untracked 파일만으로도 true 가 될 수 있다(추정, 확인 안 됨). 실행된 코드가 커밋과 같은지 확인할 수단이 없다. per-episode part npz, stage0.json, fit.json 원본은 로컬에 없어서 재분석(레벨별, 통과율의 episode CI)을 할 수 없다.
- S2. `first_batch_max_abs_diff_encoder_vs_cache` 가 0.099 다. 소거기와 레벨 평균은 fp16 캐시로 적합하고, 평가 입력은 새로 인코딩한 fp32 다. fp16 반올림만으로 0.099 가 나오려면 절댓값이 수백인 성분이 있어야 한다. DINOv2 의 큰 norm 이상치 차원이면 가능하지만 확인하지 않았다(추정). 결론에 대한 영향은 작을 것이다.
- S3. 소거 위치(확인, 버그 아님): `extract_erased` 와 `eval_batch` 는 위치 임베딩을 더하기 전에 변위를 더한다. 덧셈이므로 더한 뒤와 동일하다. 판독 블록 0 은 위치 임베딩을 더한 뒤이고, 상수 이동이라 선형 판독에 영향이 없다. 블록 0 R² 가 seed/조건 사이에서 같은 것(-0.0801)과도 맞는다.
- S4. 무작위 LEACE 대조의 부호(확인, 버그 아님): `-coef·|c|·R_k` 의 토큰별 norm 은 |coef|·|c| 로 크기 소거와 같다. 방향이 무작위이므로 부호 선택은 분포상 무의미하다.
- S5. 문서 낡음: README 3행("미실행, 결과 수치 없음")과 config.yaml 2행("미실행")이 실행 후 갱신되지 않았다. 결과 근거로 인용하면 안 된다.
- S6. 행동/proprio 좌표(404 − 384 차원)는 소거하지 않았다(README 46행, 확인). 012 기록상 행동 좌표만으로 하는 판독은 블록 1 에서 낮았다(log.md 363행). 블록 1 회복의 주경로는 아닐 것으로 추정한다. 다만 판독이 z 부분만 보므로 이 경로는 측정되지 않았다.

## 대안 설명 (가장 단순한 것부터)
1. 방향 기하만으로 설명된다. 데이터 다양체 위 방향(크기 방향, 레벨 평균 차이)의 변위는 predictor 가 그대로 통과시키고, 등방 무작위 방향은 일부 교정한다. 이 성질은 random-init 에서도 있다(통과율 0.545 대 0.312). 이것만으로 LEACE 의 음의 motion Δ_use, 양의 total Δ_use, random-init 의 0 아닌 기준값, level_mean_match 의 작은 양수가 모두 설명된다. 크기 "사용"을 가정할 필요가 없다.
2. 분포 밖 입력으로 설명된다. LEACE 토큰별 적용은 프레임 간 변화보다 큰 교란이다(|δ|² 가 persist 의 약 1.8배). 오차 증가 대부분은 OoD 반응이다.
3. 정보가 그대로 남아 있다. 블록 1 회복이 보여 주듯 크기는 지워지지 않았으므로, 측정된 것은 "정보 제거의 비용"이 아니다.

## 이 결과를 믿으려면 추가로 필요한 실험 (최대 3개)
1. **크기와 무관한 다양체 위 대조.** level_mean_match 와 같은 방식으로, 레벨 라벨을 레벨 안에서 무작위로 섞은 "가짜 레벨" 평균 맞추기나 시간 단계/위치별 평균 맞추기를 norm 을 맞춰 대조로 둔다. 그 대조 대비 Δ_use 와 random-init 기준값을 다시 잰다. 대조와 random-init 에서 Δ_use 가 0 근처가 되어야 귀무가 성립한다. 기존 measure 와 같은 비용대의 순전파만 필요하다(추정).
2. **통과율에 무관한 지표로 재집계.** 이미 저장된 total/motion/disp 로 계산할 수 있는 통과율(cross/|δ|²)을 방향별로 보고한다. 변위를 출력 공간에서 제거한 뒤 잰 지표(예: δ 의 직교 여공간에서 pred − z_e 와 Δz 비교, 또는 다음 프레임에도 같은 변위를 더한 z1 + δ 를 목표로 하는 오차)를 사전 등록하고 재집계한다. part npz 만 있으면 CPU 로 가능하다. 단, 결과를 본 뒤의 지표 변경이므로 탐색적 분석으로만 표시해야 한다.
3. **predictor 안에서 유지되는 소거.** 블록 0..6 의 모든 깊이에서(009 방식) 또는 토큰 수준 판독기(attentive/MLP) 기준으로 소거를 반복 적용해 블록 1-6 판독 R² 가 0 근처로 유지되는지 먼저 확인한다. 그 상태에서 같은 Δ_use 를 잰다. 블록 1 회복이 남아 있으면 어떤 Δ_use 도 "사용"으로 해석할 수 없다.

## 확신도

- C2(motion 지표가 통과율에 좌우되고 부호가 지표 선택으로 뒤집힘): **높음.** 항등식은 코드 정의에서 바로 나오고, 부호 반전은 results.json 에서 확인했다. 단, 통과율 차이의 원인(다양체 위/밖, LayerNorm 등)은 추정이다. 통과율은 seed 0 의 episode 평균에서 유도한 점추정이고 CI 가 없다.
- I1-I4: **중간.** 수치는 확인했지만, "LEACE 변위 대부분이 크기와 무관한 토큰 내용 제거"와 "관문 비가 렌더링 효과"라는 설명은 직접 측정이 없는 추정이다.
