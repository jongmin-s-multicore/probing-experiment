baseline 기울기(001, ol@k12): s0 0.2366, s1 0.3102, s2 0.1500. 규칙을 한 줄씩 확인한 결과 구현이 config 문구("모든 쌍 >= 0.2 이면 pass, 모든 쌍 |차| < 0.2 이면 fail, 나머지 not_evaluable")와 같다. 두 가지 구현 해석(all_untrained, all_pairs)은 README 에 "구현자 해석"으로 적혀 있고, 이 리뷰는 그 해석을 그대로 따랐다.

규칙 자체에 대한 지적(통계 관점):
- H-H1 의 c(비율이 1 을 가로지르는 크기)는 크기별 평균 비율의 부호 변화 한 번에 의존한다. 한 점의 작은 차이로 정의 여부가 바뀐다. 예: single_a248 의 훈련 크기(a248) 비율이 s0 1.036 [0.989, 1.078], s1 1.028 [0.991, 1.065], s2 0.899 [0.856, 0.940]. s0, s1 은 CI 가 1 을 포함하는데 평균이 1 을 3% 넘었다는 이유로 "교차 없음, c = null" 이 되었고, s2 는 0.899 라서 c = 2.209 가 정의됐다. 세 시드가 물리적으로 다른 행동을 한다고 보기 어렵다(a248 의 기울기 0.527, 0.577, 0.552).
- 사전 등록 통계량은 "에피소드별 비율 ol/max(real,1) 의 평균"이다. 실제 면적이 작은 에피소드(최소 0, 다음 29, 44 px; 천이 화면 밖) 때문에 꼬리가 무겁다. single_a026_s0 의 훈련 크기 a026 에서 평균 비율 1.704 [0.931, 2.708] 인데, 평균 ol 면적 / 평균 real 면적은 453.2/487.65 = 0.929 이다. 즉 "a026 에서 비율이 1 을 넘는다"는 사실 자체가 추정량 효과다.

## 2. 추정량 민감도 (과제 1, 2 보조)

코드: stats_review.py 의 "estimator sensitivity" 블록(결과는 stats_review_output.json 의 sensitivity.estimator_ratios, estimator_variants_h1).

- single_a026 s0, s2: 평균의 비율(ratio of means)이나 중앙값 비율로 바꾸면 모든 크기에서 비율이 1 미만이라 c 가 정의되지 않는다(no_crossing_all_below). 사전 등록 추정량에서는 a026 → a040 사이에서 1 을 교차해 c = 0.341(s0), 0.334(s2).
- single_a026 s2 의 a060 비율: 평균의 비율 CI 는 [0.444, 1.072] (저장 CI 그대로). 20개 부트스트랩 시드로 상한만 다시 뽑으면 1.054 ~ 1.086 으로 항상 1 이상. 이 CI 가 1 을 포함한 이유는 꼬리다. 해당 100 에피소드의 비율 분위수는 최소 0.046, 중앙 0.432, 99% 1.819, 최대 18.667 이고, real 최소가 15 px 이며 비율>1 인 에피소드가 6개다. 평균의 비율로 CI 를 다시 계산하면 [0.394, 0.473], 중앙값 비율 CI 는 [0.386, 0.482] 로 1 을 명확히 배제한다. 즉 s2 가 "CI 조건 실패"로 기록된 것은 평균 추정량의 꼬리 때문이고 신호가 약해서가 아니다(추정: 같은 조건에서 다른 시드와 구분할 근거는 없다).
- single_a248: 평균의 비율로는 s2 만 c 가 정의된다(0.786 로 훈련 크기 쪽이 아니라 ind 쪽으로 계산됨), 중앙값 비율로는 s2 가 supports_h1 이 아니다. 즉 H-H1 의 per-seed 결과가 추정량 선택에 따라 달라진다.

결론: H-H1 의 per-seed 판정은 데이터의 안정적인 성질이 아니라 평균 비율의 꼬리와 한 점의 부호에 의존한다. 이 규칙으로는 시드 일관성이라는 사전 기준을 만족하기 매우 어렵다.

## 3. 붕괴 run 제외와 민감도 (과제 2)

### 3.1 측정 실패인가

예. 근거(results.json 의 by_size, 코드 stats_review.py "a026_flatness" 블록):
- exp003_single_a026_s1: 900 에피소드 중 900 에피소드가 area_ol = 0 (크기별 area_ol_mean 전부 0.0). mix_adjacent_s0 도 area_ol_mean 전부 0.0 (results.json by_size).
- log(max(area,1)) 하한 때문에 그룹 평균 log(ol) = 0 이 상수가 되어 기울기가 정확히 0.0, CI 가 [0.0, 0.0] 이 된다. 비율은 0/max(real,1) = 0, c 는 "유효 평균 비율 없음"(log 0 불가)으로 null 이 된다. 이 0.0 은 "크기를 완전히 무시하는 모델"이 아니라 "마스크가 아무것도 못 찾음"이다. 크기를 무시하는 실제 평탄 예측이면 log(~480) = 6.2 가 상수가 되어 기울기만 0 이고 log 값은 0 이 아니다. 두 경우는 ol 면적 평균 0 대 약 450 으로 구분된다.
- 운영 로그 값: 두 run 모두 epoch 3 에 val_img_mse_reconstructed 가 급등해(mix_adjacent_s0 0.0030 → 0.0787, 배율 26.6; single_a026_s1 0.0015 → 0.0333, 배율 21.6) 끝까지 유지된다. 정상 15개 run 의 epoch 간 최대 배율은 1.39(중앙값 1.03)이다. 따라서 학습 중 디코더가 깨진 것이 추출 전부터 있었다(추정, 원인 미확인).
- 참고로 운영 로그 값에서 collapse epoch 의 val_z_visual_err_pred 는 같은 분포 정상 run 대비 mix_adjacent_s0 최종 0.206 대 0.183(+12%), single_a026_s1 0.131 대 0.1267 평균(+3%). mix_adjacent_s0 는 디코더 외 예측기 쪽도 조금 나빠졌을 가능성이 있다(추정, 시드 1개).

### 3.2 두 run 을 제외하거나 재학습 값이 어떤 값이어도 전체 판정이 바뀌는가

코드: stats_review.py "2. sensitivity" 블록. 결과: 바뀌지 않는다.

H-H2 (규칙: 한 분포가 pass 이려면 시드 3개 x baseline 3개 = 9쌍 전부 차이 >= 0.2; 전체 pass 는 두 분포 모두 pass 일 때만):
- mix_adjacent 의 정상 두 시드(s1 0.5023, s2 0.4153)와 baseline 3개의 6쌍만으로 이미 차이가 0.2658, 0.1922, 0.3524, 0.1788, 0.1052, 0.2654 이다. 3쌍은 >= 0.2 이고 3쌍은 |차| < 0.2 여서 mixed 이다. 따라서 s0 슬롯이 -0.5 ~ 1.5 의 어떤 값(401점 격자 확인)이어도 mix_adjacent 는 pass 도 fail 도 될 수 없다. 두 run 제외 시는 유효 시드 2개 < 3 이라 not_evaluable.
- 그러므로 H-H2 전체는 s0 값과 관계없이 not_evaluable. 격자의 모든 값에서 전체 상태 집합은 {not_evaluable} 하나뿐.
- (사전 등록 임계 0.2 는 바꾸지 않는다. 참고로만: s1, s2 의 6쌍이 모두 통과하려면 임계가 0.1052 이하여야 한다.)

H-H1 (규칙: 두 단일 모델 모두 3 시드가 같은 방향이어야 pass/fail):
- single_a026: s0 는 supports_h1, s2 는 supports_h1 아님(a060 CI 가 1 을 포함, 위 2절) 이고 supports_center 도 아님. 따라서 s1 이 어떤 값(h1, center, 둘 다 아님)이어도 패턴은 mixed 이고, s1 이 null 이면 유효 2개 < 3 이라 not_evaluable. pass/fail 불가.
- single_a248: s0, s1 의 c 가 null (평균 비율이 모든 크기에서 1 초과), s2 만 정의 → 유효 시드 1개 < 3 이라 not_evaluable. 붕괴와 무관.
- 가정을 풀어 보는 변형(규칙 변경이므로 판정이 아니라 민감도): "모든 크기에서 비율>1 이면 c >= 훈련 크기로 보고 supports_h1"로 읽으면 a248 의 세 시드 모두 supports_h1 이 되어 패턴 h1. 그래도 single_a026 이 pass 도 fail 도 아니므로 H-H1 전체는 not_evaluable. H-H1 이 pass 가 되려면 (a) 재학습한 s1 이 h1 이고 (b) s2 의 a060 CI 조건이 뒤집히고 (c) a248 의 null 이 지지로 해석되어야 한다. 세 조건 모두 사전 등록된 규칙에서는 일어나지 않는다.

mix_adjacent 와 mix_wide 의 pair 차이: mix_wide 9쌍 차이는 0.3406 ~ 0.6542 (최소 0.3406 = s1 대 baseline s1; 여유 0.1406). mix_adjacent 는 정상 6쌍이 0.1052 ~ 0.3524. 두 분포가 다른 판정이 되는 것은 mix_adjacent 의 기울기(0.50, 0.42)가 baseline 최댓값 0.31 + 0.2 = 0.51 에 거의 닿는 위치이기 때문이다.

mix_wide 가 뒤집히려면: 최소 mix 기울기 0.6508 이 유지될 때 baseline 최댓값이 0.4508 이상이어야 하고(현재 0.3102), baseline 최댓값이 유지될 때 mix 최솟값이 0.5102 이하여야 한다(현재 0.6508). baseline 시드 SD 는 0.0802 이므로 baseline 1개가 +1.7 SD 정도 높은 값이 나오는 정도의 변동에서 뒤집힌다. 추정이며, 시드 3개로 이 분산 추정 자체가 불안정하다.

- run 내부 부트스트랩 CI 반폭은 약 0.04 ~ 0.05 (mix_wide 평균 0.048, baseline 0.054)인데 시드 간 SD 는 0.08 ~ 0.09 이다. 시드 변동이 에피소드 샘플링 변동보다 크다. 그러므로 run 안 CI 가 겹치지 않는다고 시드 운을 배제할 수 없다.
- 효과 방향은 분명하다: mix_wide 의 시드 3개 개별 CI 하한(0.600, 0.748, 0.756)이 baseline 3개 상한(0.288, 0.361, 0.211)보다 모두 위. 그러나 이 비교는 baseline 이 다른 실험이다(5절).
- single_a248 의 기울기 0.527 ~ 0.577 이 baseline 보다 크다는 것도 같은 한계 안에서 관측 사실이다(시드 SD 0.025로 가장 조밀). 여기서 기울기만으로 "훈련 크기로 끌림"을 말할 수는 없다. 규칙상 H-H1 에 쓰이는 것은 c 와 CI 조건이다.

### 4.1 single_a026 s0, s2 의 낮은 기울기: 측정 실패인가 신호인가

코드: stats_review.py "a026_flatness" 블록, 그림 fig_ol_vs_real_means.png (왼쪽).
- s0: 크기별 평균 ol 면적 [453, 501, 537, 473, 494, 482, 422, 485, 485] px, 훈련 크기 real 평균은 487.65 px. 즉 크기별 ol 평균이 모든 평가 크기에서 훈련 크기 면적의 0.87 ~ 1.10 배(즉 예측이 거의 일정). 평가 real 면적은 488 → 5476 (11배)로 변하는데 ol 은 변하지 않는다. 평균 ol 과 평균 real 의 스피어만 상관은 -0.13. 하한 효과는 거의 없다(ol 면적이 0 인 에피소드는 900 중 2개).

- s0 와 s2 의 기울기 차이 +0.143 은 두 run 의 부트스트랩 차이 CI [0.039, 0.251] 로 run 내 샘플링 변동만 고려해도 0 은 제외하지만 하한 근처이고, 시드 SD(mix_wide 0.088, baseline 0.080)의 1.6 ~ 1.8 배 안이다. 즉 같은 조건의 시드 변동 범위 안에 있다. 여기에 s0 는 재개 run 이라는 교란이 겹쳐 있어 분리할 수 없다(5절).
- 비율 평균 기준의 H-H1 판정 문제는 2절에서 다뤘다. a026 모델은 훈련 크기에서도 ol 면적 평균(453, 438)이 real(488)보다 약간 작다. 평균 ol/real 비율이 모든 크기에서 1 미만이어서 "비율=1 교차"는 이 모델에서 정의하기 어렵다.

## 5. 붕괴 빈도와 총 손실로 탐지 가능한가 (과제 4)

코드: stats_review.py "4. 18 run" 블록, 표: analysis/recon_18runs.csv, 그림: fig_recon_by_epoch.png. 아래 값은 모두 **운영 로그 값**(epoch_logs.jsonl 에서 복사한 analysis/decoder_recon_by_epoch.json)이다. results.json 값이 아니다. 18 = 003 의 12 run + 002 의 6 run. 001 의 3 run 은 마지막 epoch train 지표만 있어 제외(001 train 재구성 MSE 0.00069 ~ 0.00072, 정상 범위로 추정).

- 붕괴 정의(코드): 마지막 값이 run 내 최솟값의 5배 초과이고 epoch 간 최대 배율이 5 초과. 해당 run: mix_adjacent_s0, single_a026_s1 (두 개). 임계값 5 는 이 분석에서 정한 값이고 사전 등록이 아니다. 최대 배율 21.6 과 26.6 에 비해 정상 16개는 최대 1.39 라 5 라는 선택에 민감하지 않다.
- 빈도: 2/18 = 11.1%. Wilson 95% CI [3.1%, 32.8%], Clopper-Pearson 95% CI [1.4%, 34.7%]. 003 만이면 2/12 = 16.7% (Wilson [4.7%, 44.8%]). 002 6 run 중 붕괴는 0 이므로 003 에서만 일어났다. 같은 조건의 반복이 아니라 서로 다른 분포에서 우연히 2개가 나왔다. 두 개 모두 epoch 3 에서 일어났다는 점이 우연인지 공통 원인(예: 같은 Colab 세션, 데이터 로더 이슈)인지는 이 데이터로는 구분되지 않는다(추정).
- 총 손실 val_loss 로 탐지:
  - 같은 분포의 정상 run 과 비교하면 쉽다. mix_adjacent_s0 val_loss 0.2658 대 정상 두 시드 0.1894, 0.1890 (+40.5%). single_a026_s1 0.1608 대 0.1274, 0.1275 (+26.1%). 정상 같은 분포 시드 간 차이는 0.0004 이하. 
  - 분포를 가로질러 절대값으로 탐지하는 것은 불가능하다. 전체 18 run 에서 붕괴 run 의 val_loss 가 높은 쪽에 있을 확률(AUC)은 0.5625 뿐이다. single_a026_s1 의 0.1608 은 정상 run 14개의 val_loss 보다 낮다(single_a248 0.229, mix 0.189 등).
  - val_loss 는 디코더 재구성 항을 포함하는 것으로 보인다(추정: val_loss - val_z_visual_err_pred 가 재구성 MSE 와 크기가 비슷, 정확한 정의는 확인하지 못함). 따라서 손실이 높아지는 것은 디코더 붕괴의 결과이고, 독립 탐지 신호가 아니다.
  - epoch 단위 val_loss 상승 배율(epoch 간)은 두 붕괴 run 에서도 0.997, 0.998 로 정상과 구별되지 않는다. 총 손실이 단조 감소하는 중에 일어나기 때문이다.
- 결론: 총 손실 단독으로는 분포를 고려하지 않으면 붕괴를 탐지할 수 없다. 탐지 가능한 신호는 재구성 MSE 의 epoch 간 배율(붕괴 21.6, 26.6; 정상 최대 1.39)과 같은 분포 시드 간 비교다. 단, 같은 분포 시드가 3개뿐이라 "정상 기준"을 시드 2개로 잡으면 SD 추정이 불안정하다(z 값 237, 389 같은 수는 의미가 없고 상대 초과폭 +26 ~ +40%만 신뢰할 수 있음). 붕괴 run 이 섞인 상태에서 leave-one-out 비교를 하면 정상 run 의 기준이 오염된다(코드의 valloss_detect_same_dist 에서 정상 run 의 peer_mean 이 높게 나온 이유).
- 18개 중 2개 붕괴는 표본이 작아 발생률 추정이 매우 넓다(위 CI). 정상 run 에서의 재구성 최소 도달 후 상승 배율은 최대 1.07배 수준(recon_final_over_min)이다.

## 6. 재개 run 과 baseline 이 다른 실험이라는 점 (과제 5)

코드: stats_review.py "5. resume / baseline comparability" 블록.

### 6.1 재개 run (single_a026_s0, single_a248_s2)

- single_a248_s2 (재개, A100): 기울기 0.5518 은 s0 0.5269, s1 0.5774 사이. 운영 로그 값 최종 val_loss 0.2291 (다른 시드 0.2298, 0.2293), 재구성 MSE 0.0027 (0.0026, 0.0028). 재개 영향의 증거가 없다. 다만 단일 사례다.
- single_a026_s0 (재개, L4에서 A100로 변경; 확정 기록 11에 따르면 epoch 1 부터 새로 학습한 것으로 추정되고 재개 로그 없음): 기울기 0.0022 로 정상 시드 s2 의 0.1447 과 다르다. val_loss 0.1274 대 0.1275, 재구성 0.00119 대 0.00119 로 학습 곡선은 거의 같다. 기울기 차이(0.143)는 4.1절대로 같은 조건 시드 SD 범위 안이다. 재개 효과와 시드 효과는 정상 시드가 s2 하나뿐이라 분리할 수 없다. 재개 때문이라는 증거도 아니라는 증거도 아니다.
- 결론: 재개로 결과가 바뀌었다는 통계적 증거는 없으나, 표본이 재개 run 마다 같은 조건의 비재개 run 1 ~ 2개뿐이라 검정력이 거의 없다. 재개 사실은 표에 표시했다(per_run_slopes.csv 의 resumed 열). 또한 mix_wide 3개의 train_env 는 기록 없음(trained before the per-run record existed; GPU, 재개 여부 미기록)이라 재개되지 않았다는 보장도 없다. mix_wide 는 save_every_x_epoch 5 로 학습한 것만 기록돼 있다.

### 6.2 baseline 이 001 의 값이라는 점이 mix_wide pass 해석에 주는 영향

- 비교는 mix_wide(003, Colab, A100 등 학습 환경은 run 별로 mix_wide 는 미기록) 대 baseline_single(001, 서버, 다른 실행). 같은 파이프라인에서 재학습한 baseline 이 아니다. 같은 test split 이라도 평가 에피소드 실제 면적이 약간 다르다: k12 real 평균 면적 상대 차이가 크기별 0.02% ~ 0.68% (a026 에서 487.65 대 484.35). 마스크/추출 버전 차이 또는 일부 에피소드 차이의 가능성이 있고 원인은 확인하지 못했다.
- 훈련 손실 수준도 다르다: 001 baseline 마지막 epoch train_loss 0.1712 ~ 0.1722, 003 mix_wide train_loss 0.1864 ~ 0.1868 (분포가 달라 당연한 차이일 수 있다; 같은 비교가 아님).
- 이 교란은 pass 의 방향을 뒤집을 만큼 큰지 알 수 없다. 효과 크기가 크다는 점(여유 0.14, 평균 차 0.52)은 교란이 있어도 pass 를 지지하는 쪽이지만, "실험 간 오프셋"이 시드 SD(0.08)의 1.8배만 되어도 최소 쌍 여유(0.1406)가 사라진다. 이를 배제할 자료가 없다(002 results.json 의 runs 항목이 비어 있어 같은 단위의 ind 단일 기울기를 002 에서 가져올 수 없었다. 002 에서 다른 경로로 얻을 수 있는지는 확인하지 못했다).
- 따라서 mix_wide pass 의 정확한 의미는 "001 의 baseline 3개 값과 비교하여 9쌍 모두 +0.2 이상"이다. "크기 혼합 학습이 수축을 줄인다"는 일반화 주장은 같은 파이프라인의 ind 단일 재학습 baseline 없이는 약한 증거다. mix_adjacent 는 같은 방식으로 판정 불가이므로 "넓은 혼합만 효과가 있고 인접 혼합은 불분명"이라는 해석은 s0 붕괴 때문에 2 시드뿐이라 지지되지 않는다.
- 효과의 방향이 물리적으로 설명될 가능성은 별개 문제이며 통계로 판단할 수 없다.

## 7. 우연이나 시드 운으로 설명될 가능성

- mix_wide > baseline: 3 대 3 에서 모든 값이 우세. 순열로 가능한 최소 p 는 0.1 (양측)이며, 이는 증거의 강도가 아니라 표본 크기의 하한이다. 시드 운만으로 3개 모두 baseline 의 3개보다 큰 확률은 1/20 = 5% (단측, 교환 가능성 가정). 가정(같은 파이프라인)이 깨졌으므로 이 5% 도 낙관적이다.
- single_a248 이 baseline 보다 큰 기울기(0.53 ~ 0.58)도 같은 구조(3 대 3 전부 큼).
- single_a026 의 낮은 기울기: 정상 시드 2개(0.002, 0.145)뿐이며, 둘 다 baseline 3개의 최솟값(0.150)보다 낮거나 같다(0.145). 방향은 일치하지만 n=2 에서 통계적 주장은 불가능하다.
- H-H1 은 판정 불가이므로 "끝 크기 단일 학습이 훈련 크기로 수렴한다"를 지지도 반증도 할 수 없다. 관측 사실로는 a026 모델의 ol 면적은 크기와 거의 무관하게 약 450 ~ 600 px 이고, a248 모델은 ol 이 실제보다 큰 값에서 시작해(a026 평가 크기에서 비율 10.7, 16.0, 11.0) 큰 크기에서 1 로 수렴한다. 이 관측은 "훈련 크기 쪽으로 끌림"과 부합하지만 사전 등록 규칙의 통과가 아니고, 평균 비율의 꼬리 때문에 수치가 과대(예: 비율 평균 10.7 이나 16.0)일 수 있다(평균의 비율로 보면 a026 에서 1553/488 = 3.2 배).

## 8. 권고(통계 관점)

1. H-H1 의 비교 가능한 증거가 필요하면 추정량을 사전 등록하고(평균의 비율 또는 로그 비율의 평균 등) c 를 교차점이 아닌 연속 지표(예: 비율의 로그를 크기에 회귀한 기울기)로 바꾸는 후속 가설을 새로 세워야 한다. 지금의 판정 기준을 결과 후에 바꿔서는 안 된다.
2. 붕괴 두 run 은 같은 시드, 같은 설정으로 재학습하면 측정이 가능하다(CLAUDE.md 재시도 한도와 사람 승인 필요). 단, 3.2 에서 보인 대로 이 재학습은 전체 판정을 바꾸지 못한다. 재학습의 가치는 판정이 아니라 시드 수 보강에 한정된다.
3. 가장 정보량이 큰 추가 실험은 같은 파이프라인에서 ind 단일 baseline 을 3시드 재학습하는 것이다(mix_wide pass 의 해석 교란 제거).
4. 추출 단계에서 area_ol 이 전부 0 이거나 재구성 MSE 가 급등한 run 을 자동 표시하는 점검(재구성 MSE 의 epoch 간 배율 > 5)을 추가할 수 있다. 실험 코드는 수정하지 않았다.

## 9. 확신도

- 판정 재계산 일치, 붕괴 run 이 측정 실패라는 점, 두 run 이 어떤 값이어도 전체 판정이 불변이라는 점: **높음**. 규칙이 결정적이고 코드로 격자 확인했으며 저장값과 1e-15 로 일치한다.
- 추정량 민감도(평균 비율의 꼬리 때문에 H-H1 per-seed 가 불안정): **중간~높음**. per-episode 면적에서 직접 재계산했다. 다만 어느 추정량이 "옳은가"는 판단하지 않았다.
- single_a026 의 낮은 기울기가 실제 신호라는 점: **중간**. 평균 ol 면적이 평탄하고 하한 효과가 거의 없다는 것은 확실하지만, 정상 시드가 2개뿐이고 s0 는 재개 run 이다.
- mix_wide 효과의 크기와 방향: **중간**. 9쌍 규칙은 통과하나 시드 3 대 3, 정확 순열 최소 p 0.1, baseline 이 다른 실험의 값이라 일반화 주장은 **낮음**.
- 붕괴 빈도 2/18 의 일반화(발생률): **낮음**. 신뢰구간이 [3%, 33%] 로 넓고 두 건이 우연인지 공통 원인인지 모른다. 운영 로그 값이다.
- 재개가 결과에 영향을 주지 않았다는 주장: **낮음**(증거 부족이지 반증이 아님).
