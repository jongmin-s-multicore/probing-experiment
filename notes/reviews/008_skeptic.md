B 의 척도 통일은 train/interp 의 검출 문턱을 약 3~10배 높였다(추정, 004 보고서 수치와 위 산식의 조합).

## 중요

### I1. A 인코더의 보조 판정(Δ>0)이 사전 기준과 다르고, 사실상 검정이 아니다 (확인)
- 사전 기준(hypotheses.md 368행)은 "학습 시드 평균 - 2 x 학습 시드 sd > 0" 이다. 인코더에는 학습 seed 가 없다(train_seed=NA). 같은 이유로 C 는 인코더를 "계산 불가" 로 처리했다(run.py 195-197행). 그런데 A 는 probe seed 5개의 sd 로 대체했다(run.py 65, 83-84행). 두 항목이 서로 일관되지 않는다.
- 대체한 sd 는 depth 0, 6, 10 에서 정확히 0.0 이다(`unit_sd`, 인코더 train/interp/extrap 모두). 나머지 깊이도 0.0003~0.0068 수준이다. 그러니 "평균 - 2sd > 0" 은 평균 > 0 과 거의 같다. 인코더 7/7, 7/7, 7/7 은 검정 결과로 보고하면 안 된다. 사전 기준에 따르면 "계산 불가" 가 맞다.

### I2. random-init predictor 는 "정보 없음" 통제가 아니라 사실상 통과(pass-through) 통제다. Δ 의 의미가 바뀐다 (수치는 확인, 구조 원인은 추정)
- random_init predictor 의 extrap split R² 는 깊이 0~6 에서 0.8515~0.8525 로 평평하다. 이 값은 depth 0(real 0.85163)과 인코더 k=12 real(0.85163)과 같다(`A_control_relative_curve`). train(0.8338~0.8356), interp(0.5002~0.5099)도 평평하다.
- 그래서 predictor 의 Δ 는 "학습된 블록이 입력 대비 얼마나 바꿨나" 를 잰다. "우연 수준보다 정보가 얼마나 있나" 는 재지 않는다. Δ≈0 을 "크기 정보 없음" 으로도, "학습 기여 없음 = 정보 유지" 로도 바로 읽으면 안 된다. 잔차 연결이 무작위 블록을 거의 항등으로 만든다는 설명은 004 보고서 5.1-3 과 일치한다(추정, predictor 코드는 이번에 확인하지 않았다).
- 규칙 쪽의 함정: Δ 의 "하락" 은 real 의 정보 손실이 아니라 통제가 올라가서 생길 수도 있다. 예: 인코더 train 에서 depth 0 -> 2 로 random_init 이 0.458 -> 0.642 로 올라 Δ 가 0.275 -> 0.150 으로 떨어졌다. 그 사이 real 은 0.733 -> 0.793 으로 올랐다. 이 정의로 "소실" 이 관측되더라도 소실로 해석할 수 없다.

### I3. B 의 "관측됨/관측 안 됨" 규칙이 사전 기준에 없다. 사전 기준이 요구한 InD/OoD 비교도 하지 않았다 (확인)
- 사전 기준 B(369행)는 "MAE, MSE, 공통 분산 R² 로 InD/OoD 곡선을 비교한다" 고만 적었고, 판정 규칙은 없다. run.py 187-188행은 "공통 분산 R² 의 0.2 하락" 을 B 의 status 규칙으로 새로 정했다. 이 규칙을 정한 시점의 기록은 없다(results.json `status_rule` 에만 있다). 또 F1 에서 본 것처럼 이 규칙은 train/interp 에서 검출력이 매우 낮다.
- 정작 사전 기준과 004 보고서(251행 추천 1)가 요구한 "통일된 척도에서의 InD/OoD 비교"(gap, 겹침)는 계산하지 않았다. 척도 통일(B)과 학습 seed 단위(C)를 따로 적용했을 뿐 결합하지 않았다. 004 의 핵심 문제(겹침 검정이 분모 때문에 해석 불가)는 008 이후에도 그대로 남아 있다.

### I4. "결과 전 기준" 이라는 지위가 약하고, 검증할 수도 없다 (확인 + 추정)
- 008 은 004 의 real/random_init 곡선, 004 리뷰 3건, 004 보고서를 본 뒤 설계되었다(hypotheses.md 366행에 명시). 008 의 숫자는 보기 전이었더라도 그 숫자를 결정하는 원 곡선은 이미 공개된 상태였다. 그래서 A(predictor)와 B 의 결과는 예측 가능했다(F1).
- git 스냅샷 기준으로 notes/hypotheses.md 는 커밋되지 않은 수정 상태(M)다. 기준을 적은 시각과 실행 시각의 선후를 저장소 이력으로 확인할 수 없다.

### I5. 재현성 정보가 부족하고, 입력이 버전 관리 밖에 있다 (확인)

## 사소

- S1. 보조 판정 "평균 - 2 x sd > 0"(n=3)은 t > 2·sqrt(3) ≈ 3.46 과 같아 매우 보수적이다. interp 2/7, extrap 0/7 의 "Δ>0 아님" 은 "Δ=0" 의 근거가 아니다.
- S2. 보고에서 빠진 관측이 있다. predictor extrap 의 Δ 는 depth 1~5 에서 모두 음수이고, 평균 + 2sd 도 0 보다 작다(예: depth 2 -0.00969 + 2·0.00385 = -0.0020). B 의 MSE 로 보면 real extrap 은 0.1498~0.1526(depth 1~3)이고 random_init 은 0.1432~0.1434 이다. depth 6 에서는 0.1431 로 돌아온다. 크기는 작지만(MSE 약 0.009) 일관된 방향이다. status 와 "Δ>0 깊이 수" 만 보고하면 이 사실이 가려진다. 해석은 하지 않는다. 의미는 추정조차 이르다.
- S3. B 의 자기검증은 predictor/real 조합만 확인한다(run.py 146-156행). encoder 와 random_init 은 같은 코드 경로이므로 문제없을 가능성이 높다(추정). 다만 검증 범위는 이 한 조합뿐이다.
- S4. `json.dumps(..., default=lambda o: None)`(run.py 220행)는 직렬화할 수 없는 값을 조용히 null 로 바꾼다. 그러면 `vanish_delta: null`(소실 없음)과 직렬화 실패를 구분할 수 없다. 현재 결과에서 이상한 null 은 보이지 않는다.
- S5. 쓰지 않는 코드가 있다(run.py 135-137행 `lv`, `sel` 루프). 실험 이름은 "004_005" 이고 사전 기준에는 "기존 캐시" 가 입력으로 적혀 있지만, 실제로는 005 관련 계산도 캐시 사용도 없다.
- S6. 인코더 probe seed 의 sd 패턴이 이상하다. depth 0, 6, 10 은 정확히 0 이고 나머지는 0이 아니다. 같은 패턴이 004 summary.json 의 인코더 `tol`(0.0 과 0.008~0.012 가 섞임)에도 있다. probe seed 가 일부 설정(예: 정규화 강도 선택용 CV fold)에만 영향을 준다는 신호로 보인다(추정). "probe seed 5개" 를 분산 단위로 쓰는 004/008 의 모든 sd 해석에 영향이 있다.

## 004 판정과의 관계

- 008 은 004 의 H-d refuted 를 바꾸지 않고, 바꿀 수도 없다. 사전 기준대로다.
- 008 은 refuted 를 강화하지도 않는다(F1). 004 의 핵심 약점인 "검정에 특이성/검정력이 없다" 를 다루지 않았다. 통제 대비 곡선(A)은 통제가 통과(pass-through) 통제라서 그 약점을 그대로 물려받는다(I2).
- 008 이 새로 보여 준 것은 계산 사실 정도다. 공통 척도로 보면 InD(train, interp) 사이에는 큰 차이가 없고 extrap 은 MSE 로 5~6배 나쁘다. split R² 로 낸 004 의 gap/겹침 수치는 이 그림과 맞지 않는다(F2). 이것은 004 의 `ind_ood_gap` 이 오해를 낳는 지표라는 004 리뷰의 지적을 수치로 다시 확인한 것이다. H-d 판정 근거는 아니다.

## 이 결과를 믿으려면 추가로 필요한 실험 (최대 3개)

1. 공통 척도에서의 InD/OoD 겹침 검정(CPU, depth_r2.csv 만 사용): 학습 seed 별 MSE(또는 r2_common)로 gap 과 tol 을 계산한다. 퇴화한 깊이(predictor depth 0)를 포함할지와 임계값(MSE 단위)은 실행 전에 기록한다. 이것이 사전 기준 B 와 C 가 원래 묻던 질문이다.
2. 양성 대조로 A/B 규칙의 검출력 확인(009 에 결합): 009 의 개입 predictor 에 008 의 A(Δ 곡선)와 B(공통 R² 0.2) 규칙을 똑같이 적용한다. 강도 1.0 에서도 "관측 안 됨" 이면 008 의 A/B 는 검정력 없는 규칙으로 표시한다.
3. 통과 통제가 아닌 영 분포(null) 통제: CSV 에 있는 라벨 셔플 통제 대비 Δ 곡선을 계산한다. 가능하면 잔차를 끈 random-init predictor 도 쓴다. 그러면 "학습 기여" 와 "정보 존재" 를 분리할 수 있다. 정보 존재 쪽 Δ 가 모든 깊이에서 0 보다 큰지가 004/008 의 "정보 유지" 해석에 필요한 최소 조건이다.

## 확신도

- 전체: 중간~높음.
- 높음: F1, F2, I1, I3, I5. 모두 results.json 수치와 run.py/depthlib.py 코드로 직접 확인했다. 특히 F2 의 tol 비 0.845 = sqrt(10/14) 는 depth 1~6 에서 일관된다.
- 중간: I2 의 원인(잔차 연결로 인한 항등화)과 S6 의 원인(probe seed 의 작용 범위). predictor/probe 코드를 확인하지 않았으므로 추정이다.
- 낮음: S2 의 의미. 효과가 작고 학습 seed 가 3개뿐이다.
- 확인하지 못한 것: run.py 를 실행해 results.json 이 재생성되는지, 008 디렉터리가 git 에 추적되는지(스냅샷 목록이 잘려 있음).
