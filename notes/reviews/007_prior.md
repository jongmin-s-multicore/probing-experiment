## 2. 문헌과의 일치 여부

### 2.1 Dying ReLU 와 흡수 상태
- Lu et al., "Dying ReLU and Initialization: Theory and Numerical Examples" (2019, arXiv 1903.06733; 본문 미확인, 제목과 주제는 기억): 깊은 ReLU 망에서 어느 층이 전부 비활성이면 그 아래 층이 상수 함수가 되고 gradient 가 0 이라 학습으로 회복 불가(흡수 상태)라는 주장, 초기화 의존성이 주 주제. 이번 관측(블록 7 입력 100% <= 0, 출력 std 0, exp_avg 가 0 에 수렴, epoch 4 에서도 단일 run 은 회복 없음)이 이 서술과 일치한다. 단 Lu 는 초기화 시점의 붕괴가 중심이고 이번 것은 학습 도중(epoch 3) 붕괴이므로 인과가 같다고 할 수는 없다(추정).
- 코드 구조상의 일관성: blocks.7 이 전부 비활성이면 blocks.8 가중치로 가는 gradient 는 0, blocks.6 이하 전부 0. dec 모듈은 상수 입력을 받으므로 bias 만 학습된다. results.json 에서 dec.blocks.8.bias 의 exp_avg 가 0 이 아니고(7980-8001행) 출력이 입력 무관 상수 이미지이며 MSE 0.0855 가 평균 이미지 수준보다 훨씬 높다는 점이 이 구조와 맞는다(평균 이미지 수준의 MSE 는 real_across_input_std 0.100 기준 대략 0.01 로 추정; 이는 계산 추정이다). 결과적으로 이 상태는 "bias 만 천천히 학습되는 상수 디코더"로 보인다.
- 죽는 비율 자체는 대조도 높다. 대조의 blocks.7 입력 <= 0 비율이 0.83~0.85 이고 model_2 에서 최대 비율이 0.955, 0.957 이다(75596, 75618행). 즉 정상 run 도 ReLU 의 대부분이 꺼져 있어 "붕괴 = 일부 채널 사멸의 누적" 가능성이 있다(추정). 이 경우 소수의 살아 있는 채널(single_a026_s1 은 1.04% 가 살아 있음)이 마지막으로 꺼지는 사건이 붕괴 시점이다.

### 2.2 Adam 에서의 손실/gradient 스파이크
- Adam: Kingma & Ba 2015 (arXiv 1412.6980; 본문 미확인). 갱신량은 m/(sqrt(v)+eps) 형태이고 비정상 gradient 에 대한 갱신 크기는 상한이 있다(m, v 정의상 한 step 에서 대략 (1-beta1)/sqrt(1-beta2) = 약 3.16 x lr 이 상한, 이는 정의에서 계산한 추정). 따라서 "gradient 가 아주 크다"는 사실 자체가 가중치를 크게 움직이는 것은 아니다. 위험은 오히려 v 가 매우 작아진 상태에서(대조 v mean 이 약 1e-10, 학습 후반에 loss 가 0.002 수준) 갑자기 평범하지 않은 gradient 가 들어올 때 정규화된 갱신이 평소보다 훨씬 커지는 것이다.
- 관련 문헌: Molybog et al. 2023, "A Theory on Adam Instability in Large-Scale Machine Learning" (arXiv 2304.09871; 본문 미확인): Adam 의 v, m 갱신 불일치와 손실 스파이크. Chowdhery et al. 2022 PaLM(arXiv 2204.02311; 본문 미확인): 손실 스파이크를 배치 건너뛰기와 체크포인트 재시작으로 처리. Wortsman et al. 2023(arXiv 2309.14322; 본문 미확인): 작은 규모에서도 학습률과 Adam 설정이 불안정을 재현. 이 문헌들은 "스파이크 후 항상 죽은 ReLU 로 간다"를 주장하지 않는다. 일반론이다.
- 이번 결과와의 일치: (a) exp_avg_sq 가 대조보다 3~4자리 크다(1.4 x 10^3 배(mix_adjacent_s0), single_a026_s1 model_3 은 계산상 대조 7.07e-11 의 약 3.7 x 10^4 배, absmax 0.0873) 는 과거에 큰 gradient 가 있었음을 시사한다. (b) v 의 감쇠 시상수는 약 1000 step(0.999^n) 이므로 현재 값이 크다는 것은 그 사건이 마지막 수천 step 이내였다는 뜻이다. (c) exp_avg 가 비정규 하한으로 내려가려면 gradient 가 정확히 0 인 상태가 약 880 step 이상 지속되어야 한다(0.9^n 감쇠로 1e-5 규모에서 1e-45 까지의 계산 추정). 합치면 "마지막 약 1000~4000 step 사이의 큰 gradient 구간 후 죽음"이라는 서사가 가능하다(추정). 단 이 서사는 mix_adjacent_s0 에 대한 추정이고 single_a026_s1 의 정확한 시점은 이 자료로는 못 본다.
- 일치하지 않거나 약한 부분: 큰 gradient 의 크기, 단일 스파이크인지 지속적 진동인지는 체크포인트로 구분 불가. 또 "큰 gradient" 대신 "작은 v 상태에서 평범한 gradient 가 큰 정규화 갱신을 만든 것"으로도 같은 지문이 나올 수 있다(아래 3절 대안 B). 가중치 변화 기준 (4) 비해당은 "gradient 가 컸다"와 모순은 아니지만(Adam 갱신은 정규화됨) 리드의 서술 "아주 큰 gradient" 를 직접 지지하지는 않는다.

### 2.3 생성형 디코더의 상수 출력 문헌
- 생성 모델의 "mode collapse"와는 다른 현상이다(입력 조건부 디코더가 입력을 무시하는 퇴화). 비슷한 서술은 VAE 의 posterior collapse(Bowman et al. 2016; 본문 미확인)이나 오토인코더의 상수 출력이 있으나, 이쪽은 KL 항이나 정보 병목이 원인이라 이번 사례(KL 없음, quantize False, 단순 MSE)와 원인 구조가 다르다. 직접 대응하는 선행연구는 확인하지 못했다(미확인). 이번 현상은 "dying ReLU 로 인한 상수 출력"으로 보는 것이 가장 직접적이다.
- DINO-WM(Zhou et al. 2024, arXiv 2411.04983; 본문 미확인, 기억): 디코더는 예측기 학습과 분리된 선택적 모듈로 기억한다. 이 저장소 코드는 z.detach() 로 분리되어 있어(A_code_facts decoder_input_detach, decoder_loss_to_predictor) 같은 구조다. 

## 3. 해석에 맞지 않는 대안 설명

- 대안 A (점진적 사멸): 큰 gradient 없이, 정상 run 도 ReLU 비활성 비율이 0.83~0.96 으로 높아(75596, 75618행) 소수 채널만 남은 상태에서 정상 크기의 갱신이 마지막 채널을 꺼뜨렸다. 이 경우 v 가 큰 현상은 붕괴 이후가 아니라 이전의 불안정을 뜻하므로 구분 단서는 v 뿐이다. 이 단서는 위 2.2 로 "큰 gradient 구간"을 지지하는 쪽이다. 즉 A 는 약하게 불리하다(그러나 v 상승이 사멸 이전의 다른 원인에서 왔을 수도 있다).
- 대안 B (작은 v 가 부르는 큰 정규화 갱신): 대조도 후반에 v 가 1e-10 규모로 작다(35575행 등). 입력 분포가 다양한 데이터(크기, 시점)에서 평범하지 않은 배치가 오면 gradient 규모는 평소의 수십 배여도 "아주 큰" 것은 아니다. 이 경우 예방책은 clipping 보다 eps 조정, 학습률 하향, 웜업이 더 직접적이다(추정, 근거 약함).
- 대안 C (첫 conv bias 의 큰 이동이 원인): 가장 큰 가중치 변화 비율이 `upsample_b.blocks.0.bias`(상대 변화 0.75, 대조 약 0.10~0.12)다. 죽은 층(blocks.7)보다 훨씬 앞에서 시작된 이동이 하류 ReLU 입력의 평균을 음의 방향으로 밀었을 수 있다. 결과가 우연히 이 층에서 크다는 가능성도 있다. results.json 에서 blocks.6 bias 평균 -0.0140(5987행; 대조 값은 이번 세션에서 읽지 않았다 = 미확인)을 포함해 전 층의 부호 이동을 보지 않았다. 이 후보는 B 단계(층별 가중치 통계)를 더 보면 가릴 수 있다. 미확인.
- 대안 D (데이터 또는 배치의 특이성): 두 붕괴 run 이 모두 "패치 + save_every 1 + val() no_grad 유지" 그룹에서 나왔다는 003 보고서 내용(보고서 197행 부근)이 있다. 단독 원인 근거는 없다. 이번 007 은 train_env 가 대조와 같다고 적어 이 대안을 지지하지 않는다. 시드 의존 사건일 가능성이 더 높다(추정).
- 대안 E (수치 정밀도): AMP 사용 여부는 체크포인트로 구분 불가(A_code_facts). 코드에 autocast 는 없으나 Accelerate 설정의 mixed precision 은 미확인. exp_avg 값이 비정규 수치라는 점은 fp32 에서 나온 것이므로(저장 dtype 은 미확인) 만약 fp16/bf16 이었다면 해석이 달라진다. 미확인.
- 대안 F ("predictor 는 멀쩡하다"에 대한 반론): 003 보고서 표(4.5절 표, 112행 부근)에서 mix_adjacent_s0 의 최종 val_z_visual_err_pred 0.2062 가 형제 0.1851, 0.1815 보다 높다(약 12% 높음; 보고서 값이며 이번 세션에서 results.json 으로 재확인하지 않았다). single_a026_s1 은 0.1310 으로 형제 범위(0.1205~0.1329) 안이다. 시드 1개라 우연일 수 있다. 007 의 E 측정은 action, proprio 를 0 으로 고정해 정확도를 보지 않고 입력 간 분산만 본다. 따라서 "멀쩡"은 "구조상 분리되고 가중치 변화가 작다" 까지만 말할 수 있다.

| 활성화 교체(LeakyReLU, Maas 2013; PReLU, He 2015, arXiv 1502.01852; ELU, Clevert 2015, arXiv 1511.07289; GELU 등) | 죽은 ReLU 의 gradient 0 문제를 직접 제거 | dying ReLU 문제에 대한 직접적 대응이지만, 학습 중 붕괴 빈도 감소를 정량 비교한 결과는 이번에 확인하지 못했다. 중간(논리적으로 직접적, 실증 수치는 미확인) | 디코더 구조 변경이므로 기존 18개 run 과 구조가 달라진다. 디코더는 predictor 와 분리(z.detach())되어 있어 rollout 지표에는 영향이 없을 수 있다. 그러나 판독기(HSV 마스크 등)가 디코딩 이미지에 의존하는 지표(003 의 기울기 계산)는 디코더가 바뀌면 값이 바뀌므로 기존 run 과 직접 비교 불가가 된다. |
| 정규화(BatchNorm, GroupNorm 등; Ioffe & Szegedy 2015 arXiv 1502.03167; Wu & He 2018 GroupNorm arXiv 1803.08494) | 활성화 분포 안정화 | 중간 | 현재 디코더는 정규화 층이 없다(A_code_facts). 도입은 구조 변경이라 위와 같은 비교 불가 문제. |
| 학습률 하향, 웜업(Goyal et al. 2017 arXiv 1706.02677; Liu et al. 2020 RAdam arXiv 1908.03265) | 초기 불안정 완화 | 초기 구간에는 근거가 있으나 학습 중간(epoch 3)의 붕괴에 대한 근거는 약하다(추정) | decoder_lr 3e-4 를 바꾸면 디코더가 달라져 비교 가능성 훼손. 다만 디코더만의 문제이고 predictor(5e-5)는 별도 값이라 predictor 수치는 영향 없음(코드 구조상, 추정). |
| 체크포인트 선택, 붕괴 자동 감지 후 재시작 (PaLM 관행) | 실무 관행 | 중간 | 비교 가능성 유지에 가장 안전하다. 다만 이미 끝난 run 에는 해당 없음. |

공통 결론: 예방책은 모두 "다음 학습"에 대한 것이다. 이번 003 의 기존 조건과 비교 가능성을 유지하려면 predictor, action_encoder, proprio_encoder 학습은 건드리지 않고 디코더 설정만 별도 후속 단계에서 바꿔야 한다. 디코더 구조 또는 설정을 바꾸면 디코더 의존 지표(디코딩 이미지의 HSV 면적 기반 기울기)는 기존 16개 정상 run 과 다른 판독기를 쓰는 셈이 되므로 같은 표에 넣을 수 없다(추정). 예방책 도입 여부는 사람 결정이다.

## 5. 디코더만 재학습해 측정 복구하는 방법의 타당성

문헌 측면: DINO-WM 이 디코더를 predictor 와 분리해 선택적으로 두는 설계(본문 미확인, 기억)이고, 일반적으로 동결 인코더 위의 디코더 학습은 사후 학습 가능한 프로브/디코더 접근과 같은 계열이다. 선행연구가 "붕괴한 run 의 디코더만 재학습해 측정을 복구했다"는 사례는 확인하지 못했다(미확인).

코드 구조 측면 (A_code_facts):
- 지지: 디코더 입력이 z.detach() 이고 encoder 가 동결(train_encoder False)이므로 재구성 손실은 predictor, action_encoder 로 역전파되지 않는다(A_code_facts decoder_input_detach, decoder_loss_to_predictor). 따라서 해당 run 의 predictor 는 디코더 붕괴와 무관하게 학습되었을 것이고, 이론상 predictor 를 그대로 두고 디코더만 새로 학습해도 predictor 의 예측 latent 를 디코딩하는 측정은 복구 가능하다.
- 필요 조건: (a) 체크포인트에 DINO 인코더가 포함되지 않지만 torch hub 고정 commit 으로 복원 가능(007 에서 이미 같은 방식 사용). (b) 디코더를 학습하려면 학습 데이터(프레임)가 필요하다. 007 은 데이터를 내려받지 않았다. (c) 최종 model_15 가 있고 "남은 5, 10, 15 는 모두 붕괴 후"(003 보고서)이므로 predictor 는 최종 체크포인트에서 가져오고 디코더는 새로 학습하면 된다. 디코더 학습 때 predictor 출력이 아니라 실제 프레임의 DINO 잠재를 입력으로 하므로 predictor 분포 이동(rollout 예측 latent 의 분포)에 대한 디코더 일반화는 이 run 과 정상 run 과 같은 조건이다.
- 한계/교란: (1) 정상 16개 run 의 디코더는 원래 방식으로 학습된 것이고 복구한 디코더는 학습 설정(에폭 수, 시드, 초기화)이 다를 수 있어 측정 장치가 달라진다. 비교하려면 정상 run 에도 같은 재학습 디코더를 적용해야 한다(추정). 그렇지 않으면 디코더 효과가 섞인다. (2) 재학습한 디코더가 다시 붕괴하지 않는다는 보장이 없다. 붕괴 원인이 미확인이므로 원인이 데이터 순서나 학습률에서 오면 재발할 수 있다(11/18 아닌 2/18 빈도라는 003 보고서 수치는 시드 2건 기반으로 불확실). (3) 코드 5a640bed 가 003 패치(train_resume.patch)와 합쳐서 돌았으므로 재학습 스크립트는 같은 패치 상태를 써야 한다. (4) 재학습과 GPU 사용은 승인 대상(CLAUDE.md). 
- 대안: 기존 정상 run 을 모두 같은 새 디코더(한 번 학습한 공용 디코더 또는 run 별)로 다시 디코딩하는 것이 가장 비교 가능하다. 이는 비용 대비 설계 선택이라 사람 결정 사항이다.
- 추정: "실제 DINO 잠재(real z)로 학습한 디코더를 predictor 예측 잠재에 적용"하는 것이 003 의 원래 측정 방식이므로, 복구 후 측정의 의미는 원 측정과 같다. 단 predictor 가 정상이라는 전제가 필요하며 이는 3절 대안 F 대로 12% 높은 값이 있는 mix_adjacent_s0 에서 확정되지 않았다.

## 6. 빠진 비교와 인용

- 빠진 baseline: 같은 구조의 붕괴 run 이 아닌 sibling 의 epoch 2->3 구간 상세(층별 활성 비율의 추이)는 있으나, 붕괴 직전 step 단위 gradient norm, loss 는 저장되지 않았다(A_code_facts: 저장되지 않는 것). 그러므로 "큰 gradient" 가설은 체크포인트만으로는 반증 불가능하다.
- 같은 비교가 필요한 것: 대조 run 의 층별 ReLU 비활성 비율이 높은데(0.83~0.96), 이 값이 에폭에 따라 올라가는 추세인지(model_2 대 model_3 의 대조 값 비교) 보지 않았다. 대조도 같은 방향이면 대안 A 가 힘을 얻는다. 결과 파일에 대조 model_2 의 층별 값은 있는 것으로 보인다(미확인).
- 인용 필요: Lu et al. 2019(dying ReLU), Kingma & Ba 2015(Adam), Molybog et al. 2023(Adam 불안정), Pascanu et al. 2013 또는 Zhang et al. 2020(clipping). 모두 본문 미확인 상태로 인용 후보일 뿐이다.

## 7. 다음에 해 볼 만한 것 (제안, 승인 전)

1. 이미 있는 results.json 에서 대조 model_2 대 model_3 의 층별 ReLU 비활성 비율 변화와 blocks.6, blocks.7 주변 bias 의 부호 이동을 비교한다(CPU, 새 실험 불필요).

3. 재학습은 사람 결정. 하게 된다면 디코더만 재학습하고 정상 run 도 같은 방식으로 재디코딩, 활성화 교체나 clipping 은 별도 실험으로 분리.

## 8. 확신도

- 전체: 중간.
- 높음: 관측 사실(죽은 ReLU 층 특정, 상수 출력, 가중치 변화 비해당, predictor 와 디코더의 코드상 분리)은 results.json 과 코드 사실에서 직접 읽었다.
- 중간: "dying ReLU 가 원인"이라는 서사와 Lu et al. 과의 일치. 현상은 일치하나 문헌은 본문을 열어보지 않았다.
- 낮음: "아주 큰 gradient"라는 부분, 시점 추정(마지막 1000~4000 step), 단일 스파이크 여부. 체크포인트로 구분 불가이고 Adam v 의 상승은 간접 단서일 뿐이다. 또한 predictor 가 정상이라는 주장은 대안 F(12% 높음)와 E 측정의 한계로 확정할 수 없다.
- 이유: 웹 확인 없이 기억에 의존해 문헌을 적었고, results.json 의 전체 층별 통계 중 일부(blocks.6, 8 주변과 0 번 bias 등)만 읽었다. 에폭당 step 수(4125)는 step 과 파일 번호의 대응에서 계산한 추정이다.
