### (4) 10배 기준 (`crit4_null.csv`, `per_element_delta_summary.csv`)
- 6.1배는 10배 미만이므로 사전 기준상 비해당이다. 이것은 그대로 쓴다.
- 대조끼리의 null: 대조 한 개를 나머지 두 개의 최댓값과 비교한 최대 비 = 1.47, 1.23, 1.58. 붕괴 run 은 6.10, 6.09, 같은 분포 짝만 쓰면 6.10, 7.49. 즉 붕괴 쪽 최댓값은 대조 null 최댓값의 약 4배다. 10배라는 값은 사전 선택이었고, 실제 null 은 1.6 안팎이라 "10배" 는 매우 보수적인 문턱이었다. 3배 문턱이었다면 붕괴 run 에서 해당했을 것이다. 이것은 사후 문턱 변경 제안이 아니라 민감도 정보다.
- 비의 구성: 대조 최댓값 대비 비가 1 초과인 파라미터 수 = 붕괴 44/44(mix), 38/44(single); 대조의 leave-one-out 은 14~16/44. 3개 대조 최댓값 대비이므로 교환 가능하면 파라미터당 1/4 (44개 중 약 11개) 가 우연히 초과한다. 대조는 기대치 근처(14~16, 상관 때문에 약간 큼), 붕괴는 그 이상이다.
- 편향(bias)과 가중치가 갈린다: 중앙값 비 편향 2.71 / 2.84, 가중치 1.24 / 1.42 (mix / single). 최대값 `upsample_b.blocks.0.bias` 는 편향이라 노름이 작아 상대 변화가 잡음에 민감하다. 가중치 쪽 최대 비는 2.0 / 2.3. 핵심 가중치 `upsample_b.blocks.6.weight` 의 상대 변화는 0.474 / 0.423 대 대조 0.432 / 0.421 / 0.391 로 정상 범위다. 따라서 "한 층의 가중치가 폭주해서" 라는 그림은 데이터에 없다.
- Adam 때문에 "10배 기준" 자체가 gradient 크기에 둔감하다. Adam 의 한 step 크기는 lr * m/sqrt(v) 로 제한된다(스파이크 하나가 지배하는 경우 한 원소의 누적 이동량 상한 약 lr * 0.1/sqrt(0.001) / (1 - 0.9/sqrt(0.999)) = 0.0095). 가중치 변화를 보는 기준 (4) 은 "아주 큰 gradient" 가설에 대해 검정력이 낮은 기준이다. 비해당은 그 가설을 기각하지 못한다. 한편 실제 이동량(원소당 rms 중앙값 0.0076 / 0.0078 대 대조 0.0044~0.0048)은 정상 학습에서도 이 상한을 넘는 경우가 있어(`per_element_delta_summary.csv`) 단발 스파이크 가설을 판별하는 용도로 쓰지 않는다.

## 3. Adam 상태로부터의 제약 (코드와 체크포인트에서 확인한 값: betas [0.9, 0.999], eps 1e-8, lr 3e-4, weight_decay 0, amsgrad false; step 8250 / 12375 / 16500 = epoch x 4125)

### 관측 재계산 (`adam_v_ratio.csv`)
- `upsample_b.blocks.6.weight` exp_avg_sq 평균 (대조 3개 평균 5.13e-11): mix_adjacent_s0 epoch 3 9.55e-8 (1861배), single_a026_s1 2.58e-6 (50271배). 리드가 보고한 배율을 재현했다. 하지만 epoch 2 에는 각각 대조의 0.84배 / 1.23배였다. 즉 증가는 epoch 3 중에 일어났다. 그런데 다른 파라미터도 올랐다: blocks.0.weight 24배 / 88배, blocks.8.weight 145배 / 499배 (두 run 모두). 이 두 값(1861, 50271)은 44개 중 최댓값이므로(선택된 최대) 그 크기를 대표값으로 쓰면 과장된다.
- epoch 3 -> 4 (single): v4/v3 = 0.016131 (blocks.6.weight), 0.016131 (blocks.0.weight), 0.016139 (blocks.8.weight). 0.999^4125 = 0.016130. gradient 가 사실상 0 이면 이 값이 나온다. 반면 `dec.blocks.8.bias` (사망 ReLU 아래의 경로가 없는 파라미터)는 0.0663 으로 gradient 가 살아 있다. 이 일치는 "죽은 이후 상류 gradient 가 0" 을 강하게 지지한다.

### exp_avg "정확히 0" 21개 (mix_adjacent_s0 model_3)
- 정확한 사실은 0 이 아니다. 이 21개 파라미터의 exp_avg absmax 는 5.6e-45 = float32 최소 비정규수(1.4013e-45)의 정확히 4배(4.0000 단위)이고, results.json 의 norm 이 0.0 인 것은 제곱합이 float32 에서 언더플로한 결과로 추정된다(norm 필드 0.0 과 absmax 5.6e-45 가 같은 요약에 공존, `stats_007_out.json` s0_floor_absmax_in_units). 21개는 `upsample_b.*` 22개 중 `blocks.8.bias` 를 뺀 전부로, 죽은 ReLU 이전 파라미터와 정확히 일치한다(`blocks.8.weight` 의 gradient 는 blocks.7 출력이 0 이라 0, `blocks.8.bias` 는 살아 있음).
- 4 단위가 바닥인 이유: m <- 0.9 m 를 float32 비정규 구간에서 반복하면 정수 단위 k 에서 0.9k 가 반올림으로 k 로 돌아오거나(k<=4) 4 로 내려간다(k=5 -> 4). 실제로 계산하면 1,2,3,4 단위는 고정점이고 5 -> 4 (`denorm_floor`). 따라서 m 은 정확히 4 단위에서 멈춘다. 이것은 "m 이 바닥까지 감쇠했다" 는 뜻이다.
- 하한: m0 -> 약 7e-45 까지 0.9 로 감쇠하는 데 필요한 step 수 = ln(m0/7e-45)/0.10536. m0 = 1e-6 이면 834, 1e-5 이면 856, 1e-3 이면 899, 1e-2 이면 921 (`m_decay_steps`). 어떤 현실적 m0 에서도 약 830~920 step 이다. 따라서 gradient 가 정확히 0 이 된 지 최소 약 850 step (epoch 의 약 21%) 지났다. 이 하한은 m0 의 크기에 로그로만 의존해서 "큰 gradient 였는지" 는 알려주지 못한다 (m0 가 1e-6 이든 1e-2 이든 하한이 88 step 안에서 같음).
- single_a026_s1 은 exp_avg 가 바닥에 닿지 않았다(blocks.6.weight absmax 3.4e-5). 생존 채널 2개의 gradient 가 m 을 갱신했거나 사망 시점이 더 늦었을 수 있다. 그 둘을 구분할 수 없다(구분 불가).

### v 로부터 "언제, 얼마나 큰" 역산 (`adam_burst_inversion.csv`, `fig_adam.png`; mix_adjacent_s0, `upsample_b.blocks.6.weight`, 사망 후 gradient 0 가정)
v_now = 9.55e-8, 대조 v = 5.13e-11 (대조의 gradient rms = sqrt(v) = 7.2e-6). 사망 n step 전에 모든 v 가 만들어졌다면 v_death = v_now / 0.999^n:

| 사망 후 경과 n | 0.999^n | v_death / 대조 v | 단발(1 step) 스파이크로 환산한 원소 rms gradient (대조의 몇 배) | 100 step 지속으로 환산 (대조의 몇 배) |
|---|---|---|---|---|
| 1 | 0.999 | 1863 | 0.0098 (1365배) | 0.0010 (140배) |
| 855 (하한) | 0.425 | 4379 | 0.0150 (2093배) | 0.0015 (214배) |
| 1732 | 0.177 | 10530 | 0.0232 (3245배) | 0.0024 (333배) |
| 4125 | 0.016 | 115403 | 0.0770 (10743배) | 0.0079 (1101배) |

- 결론: v 는 n 과 gradient 크기를 분리하지 못한다. 같은 v_now 가 (사망이 늦고 큰 스파이크 1회) 와 (사망이 일찍이고 수십~수백 step 지속된 중간 크기 gradient) 둘 다에서 나온다. 단발 환산 1365~10743배는 "큰 gradient" 라는 서술과 맞는 숫자이지만, 100 step 지속 환산 140~1101배도 똑같이 가능하다. 그리고 활성값 자체가 상류에서 40~110배 커졌다(위 2절). weight gradient 는 입력 활성값에 비례하므로 활성 규모가 커진 것만으로 gradient 가 수십~수백배가 될 수 있다. "스파이크" 가 아니라 "규모가 커진 상태의 정상적인 큰 gradient" 일 수 있다. 따라서 "단일 큰 gradient 여부 = 체크포인트로 구분 불가" 는 계산으로도 맞다.
- 시점 제약은 체크포인트 밖에서 온다 (추정): 003 의 epoch 로그(`decoder_recon_by_epoch.json`) 에서 train_loss(epoch 평균, 디코더 재구성 손실이 가중치 1로 합산됨; val_loss 차이 0.0746 = val_img_mse 차이 0.0757 로 확인)의 epoch 3 대조 대비 초과분이 mix 0.0296, single 0.0142. 붕괴 후 정상상태 초과분(epoch 4,5 평균 val_loss 차이)이 0.0756 / 0.0339 이므로 붕괴 상태였던 epoch 3 의 비율 f = 0.39 / 0.42. 즉 사망 시작 step 약 10761 / 10650 (epoch 3 의 약 61% / 58% 지점), 사망 후 경과 약 1614 / 1725 step (`epoch_loss_gap.csv`, `stats_007_out.json` timing_valgap). 이는 위 m 바닥 하한(>=855 step)과 모순되지 않는다. 이 경우 mix 의 v 역산은 단발 환산 약 3059배, 100 step 지속 환산 약 313배.
  - 가정: (i) 사망 전에는 손실이 정상, 후에는 정상상태 손실, (ii) 전환 중 일시적 손실 급등이 없다(있다면 f 는 과대 추정), (iii) predictor 쪽 train_loss 는 대조와 같다(epoch 2 에서 초과분 3e-5, 2e-4 로 작음; 대조 두 개 사이의 epoch 3 차이 sd 0.0003), (iv) 시드마다 데이터 순서가 다르다. 첫 배치 로그(`train_img_mse_reconstructed`)는 쓰지 않았다: train.py 에서 이 지표는 매 epoch 첫 배치(`plot = i == 0`)에서만 계산되므로 epoch 3 중 시점 정보가 없다. 0.002173 이 정상인 것은 epoch 3 시작 시점(= epoch 2 말)의 값이어서다.
  - 두 run 의 f 가 0.39 와 0.42 로 가까운 것은 n=2 이므로 우연으로도 충분히 설명되고, 공통 원인의 증거라고 하기 어렵다.
- "epoch 3 말미에 사고가 났다" 는 가설은 이 추정과 맞지 않는다(f 가 작아야 한다). 그러나 이 추정은 단일 추정치(오차 범위 대략 f 0.33~0.43, 같은 데이터로 두 가지 방식 계산: `timing_est` 의 0.33~0.43)이고 가정에 의존하므로 "추정" 표시를 유지한다.

## 4. predictor 정상 주장

- 코드 사실(results.json `A_code_facts`): 디코더 입력은 z.detach(), 재구성 손실은 predictor 로 역전파되지 않고 optimizer 도 분리. 따라서 디코더의 ReLU 사망이 predictor 학습에 영향을 줄 경로가 코드상 없다. 이것이 predictor 정상 주장의 가장 강한 근거이며 실험 E 보다 강하다.
- 실험 E (`predictor_E.csv`): 출력의 입력 간 std (epoch 3): mix_s0 0.4793 대 대조 0.4793 / 0.4814, single_s1 0.4140 대 single_s2 0.4118. 상대 차이 -0.4%~+0.5%, epoch 2 는 -0.5%/-0.7%, +1.2%. 대조 두 개 사이 차이는 0.4%.
  - 한계 1: 행동과 proprio 를 0 으로 고정했으므로 predictor 는 사실상 프레임 하나의 함수로 평가됐다. 실제 행동 조건부 예측 능력(정확도)은 검사 밖이다. 또 입력 std in = 0.791 은 모든 체크포인트에서 같은 값(같은 DINO 입력)이다.
  - 한계 2: 입력 간 std 는 "출력이 입력에 따라 변하는 정도" 이지 "맞는 정도" 가 아니다. 상수 출력(붕괴)은 잡아내지만 편향이나 부정확은 잡지 못한다. std 가 같다는 것은 필요조건 중 하나(붕괴 아님)만 보여준다.
  - 한계 3: 대조 run 2~3개라 0.4% 이내 차이를 정상으로 보는 것도 해상도가 낮다.
  - 가중치 변화: predictor 의 대조 대비 최대 비 1.17 / 1.10 (대조 leave-one-out 1.18, 1.21, 1.28 안에 있다). 이 지점에서 이상 없음.
- 003 의 `val_z_visual_err_pred` 와의 관계 (`zpred_by_dist.csv`, 최종 epoch 15): mix_adjacent_s0 0.2062 대 s1 0.1851, s2 0.1815 -> 두 대조 평균 대비 +12.5%. single_a026_s1 0.1310 대 s0 0.1205, s2 0.1329 -> +3.4% (분포 짝 평균 대비).
  - 비붕괴 16개 run 에서 같은 분포의 나머지 run 평균 대비 상대 편차 sd = 7.6%, 최대 절대값 11.4%. 이 분포에 대해 +12.5% 는 약 1.6 sd (양쪽 p는 정규 근사로 약 0.1; 근사 표본 16, 분포 가정 불확실). 유의하지 않다. 분포 내 변동계수는 mix_adjacent(비붕괴 2개) 1.4%, 다른 분포 5~7%이다. 즉 mix_adjacent 의 s1, s2 가 서로 매우 가깝다는 사실이 +12.5% 를 크게 보이게 한다 (2개 짝이 우연히 가까웠을 수 있음).
  - 방향 일관성: 두 붕괴 run 에서 +12.5%, +3.4% (평균 +8%, n=2). 롤아웃 오차는 -6.4%, +10.6% 로 방향이 갈린다. epoch 3 시점 val_z_visual_err_pred 는 s0 0.6037 대 0.5886 / 0.5699 (+4.3%), single_s1 0.5439 대 0.5464 / 0.5392 (분포 짝 평균에 가깝다).
  - 해석: predictor 가 붕괴 run 에서 더 나쁘다는 증거도, 같다는 확증도 아니다. 코드상 인과 경로가 없으므로 "차이가 있다면 시드 변동" 이 기본 가설이나, 3시드로는 12% 를 시드 변동 범위 안이라고 확정할 수 없다. 가장 정직한 서술: "predictor 가 정상이라고 말할 근거는 코드 분리와 입력 간 std 가 같다는 약한 증거이며, 003 의 +12.5% 는 시드 변동으로 설명 가능한 범위(약 1.6 sd)이나 검정력이 낮다."
  - 이 +12% 는 붕괴 run 이 시드 문제인지 설정 문제인지와도 독립이다.

## 5. 18 run 중 2 붕괴로 본 후속 실험의 예상 붕괴 수 (`collapse_forecast.csv`, `fig_forecast.png`)

- 점추정 p = 2/18 = 0.111. 95% Clopper-Pearson [0.014, 0.347], Wilson [0.031, 0.328]. 분포별로는 mix_adjacent 1/3, single_a026 1/3, 나머지 4개 분포 0/3 (002 두 분포 포함). 003 만 보면 2/12 = 0.167, 002 는 0/6. 이질성은 n 이 작아 검정할 수 없다.
- N 개 run 에서 기대 붕괴 수 (괄호는 p 의 95% CP 하한~상한 적용):

|---|---|---|---|---|---|
| 3 | 0.33 | 0.04~1.04 | 0.30 | 0.04~0.72 | 0.37 |

- 구체 권고(통계 관점): 후속 실험이 같은 설정(같은 코드, lr, 디코더)이라면 3시드 셀 하나에서 붕괴가 0개일 확률이 약 70% 이고, 셀이 6개면 평균 0.7개 (0~2개가 흔함). 붕괴가 셀에 균등하게 퍼지지 않고 특정 셀에 몰릴 수 있다 — 붕괴 시드는 시드 단위라 셀 내 비교(예: 시드 3개 중 1개)를 오염시킨다. 설정을 바꾸면(lr, 초기화 등) 비율은 이 표를 쓸 수 없다.
- 두 붕괴 모두 epoch 3 에서 발생(`recon_max_jump_ratio` 26.6, 21.6, `jump_epoch` 3). 위험이 학습 초기 구간에 집중돼 있다는 암시는 있지만 n=2 이다. 학습 길이를 바꾸면 노출 구간이 달라질 수 있다.
- 한계: "붕괴" 판정은 003 의 collapsed 플래그(재구성 점프 비)이다. 부분 붕괴나 느린 열화는 이 비율에 안 잡힌다. 18 run 은 6개 분포 x 3시드로 같은 파이프라인이다.

## 6. 우연 / 시드 운 평가

- "두 run 모두 같은 층에서 ReLU 가 사망" 은 우연이 아니다 (효과 크기 3~5자릿수, 구조적 전파). 하지만 "왜 그 두 run, 그 시점" 은 설명되지 않았다. 18개 중 2개이므로 시드 운일 가능성이 크지만, 이 실험은 그 가설을 검정하지 못한다 (원인 비교용 대조 변인 없음).
- 대조 3개에서 같은 분석에서 비정상이 하나도 없었다(대조 사망 ReLU 0). 대조가 0/3 이므로 사망 확률의 95% 상한은 약 63% (1-0.05^(1/3)) 로, 이 대조 3개만으로는 거의 정보가 없다. 18 run 전체의 2/18 이 더 나은 근거다.
- 시드가 하나씩이므로, 붕괴 run 안에서 시드 변동과 효과를 분리할 수 없다.

## 7. 확신도: 중간 (부분별로 다름)

- 높음: criteria_table 이 results.json 원값과 사전 정의대로 재현됨; (2) 의 첫 층이 임계값 1/3~1e-4 에서 불변; ReLU 사망과 비회복의 관측 (Adam v 감쇠 일치, 003 로그).
- 중간: exp_avg 바닥 해석(4 단위 고정점)은 float32 비정규수의 반올림 계산과 단위(4.0000)가 맞아떨어져서 강하지만 PyTorch 내부 연산 순서는 코드를 직접 확인하지 않았다(추정). epoch 3 중 시점(약 58~61% 지점)은 003 로그 기반 추정으로 가정 의존.
- 낮음: 붕괴 원인(큰 gradient 여부), predictor 정상 주장의 정량적 근거(코드 분리 외), 후속 붕괴 빈도 (k=2, n=18, 설정 불변 가정).
- 이유: 붕괴 2개, 대조 3개, 시드 1개씩, 입력 54프레임(독립 아님), Adam 요약만으로는 gradient 시계열을 복원할 수 없음. 리드의 해석 중 "ReLU 사망과 비회복" 은 지지되지만 "아주 큰 gradient" 는 체크포인트로 구분 불가이고, "predictor 멀쩡" 은 코드상 분리 때문에 개연성은 높으나 이 실험의 E 검사는 약한 증거다.
