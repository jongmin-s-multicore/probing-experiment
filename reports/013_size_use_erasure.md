## 1. 한 문단 요약

DINO-WM predictor 가 크기 정보를 크기에 따라 다른 움직임을 예측하는 데 쓰는지 보려고, predictor 입력 latent 의 z 부분(384)에서 크기를 소거(스칼라 LEACE, 레벨 평균 맞추기)하고 같은 norm 의 무작위 방향 20개 소거 대비 움직임 오차 증가분(Δ_use)을 쟀다. 0단계 관문은 통과했다(6쌍 중 5쌍 비 ≥ 1.1, 비 범위 1.039-1.459). **저장된 판정은 두 소거 방식 모두 `criterion_not_met` 이다**(`rj` 직접). leace_scalar 는 (b) 의 Δ_use 가 3 seed 모두 음수(-0.179 / -0.140 / -0.126, 90% CI 전부 0 미만)이고, level_mean_match 는 조건 1(3/3)과 3((b) +0.0196 > (a) -0.0254)을 충족했지만 조건 2 에서 크게 미달했다(평균 Δ_use 0.0196, 문턱 0.0566; gap 의 약 3.5%). **세 분석가는 판정 규칙의 계산이 맞고(stats 재계산 일치, skeptic 코드 버그/누수 없음), 소거가 predictor 안에서 유지되지 않으며(선형 크기 판독 R² 가 소거 직후 블록 0 에서 -0.07 로 지워졌다가 블록 1 에서 0.64-0.77 로 회복), Δ_use 의 귀무값이 0 이 아니고(random-init 에서 LEACE 약 -0.68, level_mean_match 약 -0.18), 주 지표 motion 대신 total 로 보면 부호/결론이 달라진다는 데 일치한다.** 따라서 이 결과는 "크기를 쓰지 않는다"도 "쓴다"도 지지하지 않고, 읽을 수 있는 것은 "이 입력 소거로는 사전 기준의 사용이 검출되지 않았다"까지다. **구분해서 읽을 것**: (i) 위의 `criterion_not_met` 는 사전 규칙(주 지표 B)에 따른 확정 판정이고, (ii) 같은 3항 규칙을 지표 A(total)로 돌리면 두 방식 모두 충족된다는 것(stats 1절 재계산, skeptic 도 total 의 큰 양수를 확인)은 **사후 재계산이며 확정 주장으로 쓰지 않는다**. 어느 지표가 맞는가는 통계로 정할 수 없다는 것이 stats 의 입장이고, skeptic 은 두 지표 모두 "사용"의 증거가 아니라고 본다. **갈리는 곳**: motion 음수/양수의 의미와 어느 지표를 믿을지, level_mean_match 의 작은 양수가 크기 효과인지 방향 기하(데이터 다양체 위 대 밖)의 차이인지, (b) > (a) 의 의미, random-init 값의 쓰임(해석 지침 대 사후 귀무 변경 금지), 다음 실험의 우선순위. 결과는 학습 seed 3개(독립 단위), 소거 위치 1곳(입력), `pilot: true`, `git_status_dirty: true` 의 조건에서 나왔다. 확신 수준: 판정 재현, 소거 비유지, 귀무 비영, 지표 부호 의존은 높음(세 분석가, 수치 직접 확인), 기전 설명(통과율, 다양체, 분포 밖 입력)은 추정이며 낮음-중간, 전체는 중간 이하.

## 5. 분석가 의견 종합

세 분석가는 서로의 파일을 읽지 않고 독립 작성했다.

### 5.1 세 명이 일치한 점

1. **판정 규칙의 계산은 맞고, 두 방식 모두 사전 지표(B)로는 `criterion_not_met` 이다.** stats 가 seed 별 값에서 3항을 재계산해 일치 확인, skeptic 은 지표 정의, norm 일치, 무작위 대조 부호, 소거 위치, 적합/평가 분리에서 코드 버그나 누수를 찾지 못했다(확인), prior 는 results.json 에서 같은 수치를 읽었다.
2. **소거가 predictor 안에서 유지되지 않는다.** 블록 0 에서 R² 가 -0.07 근처로 지워지고 블록 1 에서 0.64-0.77 로 회복한다(prior 1절, stats 6절, skeptic C1). 따라서 세 명 모두 이 소거의 Δ_use 를 "크기 정보를 뺀 비용"으로 읽을 수 없다고 본다. 표현 강도는 다르다(skeptic 은 이 설계로는 양성이었어도 "사용"이라 부르기 어렵다는 쪽, prior 는 "입력 한 점 소거의 정의상 결과"라는 추정).
3. **Δ_use 의 귀무값이 0 이 아니다.** random-init 에서 LEACE 약 -0.68, level_mean 약 -0.18 로 사전 예상(약 0)과 어긋난다(prior 3절, stats 5절, skeptic C3). 세 명 모두 random-init 이 "크기를 못 쓰는 predictor"의 대리로 쓰기엔 함수 형태가 너무 다르다고 본다(정규화 분모 5.74 대 0.43 등).
4. **지표 선택이 결과 부호를 정한다.** motion 으로는 LEACE 음수, total 로는 양수(prior 3절 단위 1개, stats 3절 전 단위, skeptic C2). "검출 안 됨"(B)과 "검출됨"(A)은 같은 데이터에서 나온다. 세 명 모두 어느 쪽도 "사용 여부"의 증거로 단정하지 않는다.
5. **`criterion_not_met` 는 "사용하지 않음"이 아니다.** README 20행 단서와 같고, 세 명 모두 이 단서를 지지하거나 더 강하게 말해야 한다고 본다.
6. **level_mean_match 의 양수는 작다.** 평균 Δ_use 0.0196 은 gap 의 3.5% 로 사전 기준 10% 에 크게 못 미친다(prior 1절, stats 2절, skeptic I2: 조건 2 크게 미달).
7. **LEACE 의 무작위 방향 대조는 이 소거의 정보 제거량과 맞춰져 있지 않다.** 방향 기하(분포 안 대 밖)가 대안 설명이라는 점에서 방향이 같다: prior(최소 변경 방향 대 분포 밖일 수 있는 등방 무작위), stats(분포 밖 반응의 방향 의존성; 8절), skeptic(I1, I2). 세부 기전은 모두 추정이다.
8. **0단계 관문은 약하다.** 비 1.04-1.46, 5/6 통과이지만 효과가 작다(prior 3절 "사용 검출 실패는 사용할 유인이 약하다와 구분 안 됨", stats 0절 "전제가 약하게만 성립", skeptic I4 "물리 동역학 차이가 아니라 공변량 이동/렌더링 효과일 수 있음"). 강도와 해석은 각자 다르다(5.2절).
9. **통계 단위가 약하다.** 학습 seed 3개, CI 는 episode 재표집만 반영(stats 7절, skeptic I2). prior 도 results.json 전수를 검토하지 못했다고 밝혔다.

## 6. 한계와 위험

- **이 설계로는 "사용" 질문을 검정하지 못했을 가능성.** 소거가 블록 1 에서 회복되고(4.5절), 귀무가 0 이 아니며(4.6절), 주 지표가 변위 통과율에 좌우된다(4.4절). 세 가지 모두 results.json 의 수치로 확인된 사실이고, 그로부터 "Δ_use 는 크기 정보를 뺀 비용이 아니라 특정 방향의 변위를 넣었을 때의 비용"이라는 읽기는 skeptic 의 해석이다(추정).
- **지표 의존.** 같은 규칙에서 B 는 두 방식 모두 미충족, A 는 두 방식 모두 충족. A 의 결과는 사후 재계산이며 확정 주장이 아니다. B 의 수식을 사용자가 결과 전에 확인했는지는 기록을 찾지 못했다(skeptic).
- **random-init 귀무 문제의 양쪽 위험.** (i) 0 을 귀무로 두면 귀무 위치가 틀리다. (ii) random-init 을 귀무로 바꿔 빼면 level_mean_match (b) 가 gap 의 약 35% 가 되어 "강한 사용"처럼 보이나 사후 선택이다(skeptic C3). 어느 쪽도 이 보고서는 채택하지 않았다.
- **방향 기하 교란.** 크기 방향 변위는 데이터 위 방향, 무작위 방향은 등방 가우시안으로 대부분 다양체 밖일 수 있다(추정). 따라서 level_mean_match 의 작은 양수와 LEACE 의 음수 모두 크기 정보와 무관한 방향 기하로 설명될 수 있다(skeptic 대안 1, prior H2, stats 8절).
- **(b) vs (a) 비교의 교란.** 판정 split 의 2/3(a060, a160)가 (a) 에게는 OoD 이고 소거 없음 gap 이 다르다(skeptic I3, stats 2절). 레벨별 분해용 part npz 를 받지 않았다.
- **표본 단위.** 학습 seed 3개, 체크포인트 조건 2개, 소거 방식 2개, bootstrap CI 는 episode 표집만 반영, 학습 seed t 구간은 df=2 로 넓다. 방향 20개와 소거기 적합 분할은 고정되어 있다.

## 7. 다음 단계 후보 (제안만, 사전 등록 값은 바꾸지 않는다)

013 은 확정 설정의 실행이 끝났다. 아래는 모두 새 사전 등록과 사람 승인을 전제로 하며 013 의 판정을 바꾸자는 제안이 아니다. 출처는 분석가이며 합의된 우선순위가 아니다.

**CPU 로 가능한 확인 (part npz 를 받아야 하는 항목이 많음; 가능 여부 미확인)**
1. **part npz 를 받아 CPU 재분석**(skeptic 추가 실험 2, I3): 레벨별 값((a)-(b) 를 ind 만으로 비교), 통과율 `cross/abs(δ)^2` 의 방향별 보고와 episode CI, 통과율에 무관한 지표(δ 의 직교 여공간 비교, 또는 z1 + δ 를 목표로 하는 오차)의 재집계. **결과를 본 뒤 지표 변경이므로 탐색적 분석으로만 표시**(skeptic). 사전 등록 후에 진행.
2. **보고 방식 정리**(stats): 판정표 단독 서술 대신 B/A 병기, 효과 크기(gap 대비 %), 방향 순위, split 별 값(4.7절)을 함께 제시.
3. **확인 사항 정리**: `git_status_dirty` 원인, `pilot: true` 처리, 낡은 문구 갱신, CHANGES.md 5 정정.

**GPU 가 필요한 후속 (승인 대상, 비용은 분석가들이 추정하지 않음)**
4. **predictor 안에서 유지되는 소거**(skeptic 추가 실험 3, prior H1): 블록 0..6 모든 깊이에서(009 방식) 또는 토큰 수준 판독기 기준으로 소거를 반복 적용해 블록 1-6 판독 R² 가 0 근처로 유지되는지 확인한 뒤 같은 Δ_use 를 잰다. 블록 1 회복이 남으면 어떤 Δ_use 도 "사용"으로 해석할 수 없다(skeptic).
5. **크기와 무관한 데이터 방향 대조**(skeptic 추가 실험 1, prior H2·빠진 baseline 1): 레벨 라벨을 레벨 안에서 섞은 "가짜 레벨" 평균 맞추기, 시간 단계/위치별 평균 맞추기, 또는 데이터 분산에 비례한 무작위 변위를 norm 을 맞춰 대조로 둔다. 대조와 random-init 에서 Δ_use 가 0 근처가 되어야 귀무가 성립한다(skeptic). 순전파만 필요(skeptic 추정).
6. **oracle 크기 조건화 실험**(prior 빠진 baseline 4): 크기 레이블을 입력으로 받는 predictor 와 크기를 모르는 평균 predictor 의 motion 오차 차이로 "크기를 쓰는 것이 이득인 정도 자체"를 본다(prior 의 제안; 013 설계에 포함되지 않았고 상세 설계 없음). 0단계 관문의 ridge 비는 거친 대리이다.
7. **교체(interchange) 대조**(prior 빠진 baseline 2, H3): 레벨 평균 교체(a060 입력에 a160 평균)가 (b) 에서 예측 Δz 를 교체 레벨 방향으로 옮기는지. 짝 episode 없이도 가능하다고 prior 는 적었다(추정).
8. **학습 seed 증가**(리포터 정리): stats 7절은 seed 간 분산이 bootstrap CI 보다 크고 n=3 이 seed 모집단 추론으로는 약하다고만 적었다. 분석가 중 누구도 증가를 명시적으로 제안하지 않았고 구체 수치도 없다.
9. **지표 보정**(prior H4): 정규화 분모를 맞춘 지표(예: 동일 입력 복사 오차 기준)로 학습 모델과 random-init 을 직접 비교하는 방안(추정, 검증 설계 없음).

**저비용 정리**
10. 보고서/논문 문구: `criterion_not_met` 를 단독으로 쓰지 않고 "이 소거는 블록 1 에서 선형 판독이 회복되고(R² 0.64-0.77), 귀무가 0 이 아니며, 지표를 total 로 바꾸면 사후 재계산상 충족으로 바뀐다"를 함께 적는다(prior, stats, skeptic 공통 지점). A 판정은 사후라고 명시.
11. 문헌은 원문 확인 후에만 인용(prior 4절 6번 목록; 전부 [미확인] 또는 초록 수준).

## 8. 사람이 결정해야 할 사항

1. **결과 지위와 B 수식의 사전 확인 여부**: `pilot: true`, `git_status_dirty: true` 로 남은 이 본 실행을 본 결과로 인정할지 pilot/dirty 로 둘지, 그리고 motion 수식(`CHANGES.md` 2)을 사용자가 결과 전에 확인했는지(skeptic 은 기록을 "찾지 못함", 리포터도 확인 못함)와 낡은 상태 문구/GPU 승인 기록 보완 방식.
2. **주 지표 선택 문제**: 사전 확정된 B(motion, 두 방식 `criterion_not_met`)를 유지할지, 사후 재계산인 A(total, 두 방식 3항 충족)를 어떤 지위로 둘지(사후이므로 확정 주장 불가, 탐색으로만 표시할지), 통과율에 무관한 새 지표를 사전 등록할지, random-init 을 귀무로 쓰는 해석은 사후 선택이라는 skeptic 지적을 받아들일지.
3. **후속 실험과 GPU 승인**: part npz 를 받아 CPU 재분석(7절 1번)을 먼저 할지, 블록별로 유지되는 소거(4번), 크기 무관 데이터 방향 대조(5번), oracle 크기 조건화 실험(6번) 중 무엇을 사전 등록하고 GPU 를 승인할지.
